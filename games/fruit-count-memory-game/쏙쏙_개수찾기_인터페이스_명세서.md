# 쏙쏙 개수찾기 인터페이스 명세서

문서 버전: v1.0  
작성일: 2026-05-29  
대상 게임: 쏙쏙 개수찾기  
서비스용 game_key: `counting_fruits`  
구현용 gameId: `fruit-count-memory-game`  
기본 진입 파일: `games/fruit-count-memory-game/index.html`

이 문서는 `시니어_인지_웹게임_인터페이스_명세서_템플릿`을 기준으로, 쏙쏙 개수찾기 전용 실행 모드, config, 결과 로그, 케어 모드 접근성 정책을 정리한 문서입니다.

중요: 케어 모드는 `care` 하나로만 정의합니다. 문서와 운영 정책에서는 케어 모드를 난이도별로 분리하지 않습니다.

---

## 1. 게임 개요

쏙쏙 개수찾기는 과일 이미지를 일정 시간 보여준 뒤, 사용자가 목표 과일의 개수를 기억해 선택하는 인지 훈련 게임입니다.

주요 훈련 영역은 다음과 같습니다.

| 영역 | 설명 |
|---|---|
| 시각적 주의 | 화면에 제시된 과일을 살펴보고 목표 과일을 구분 |
| 작업 기억 | 과일이 사라진 뒤 개수를 떠올림 |
| 수량 판단 | 목표 과일의 개수를 선택지에서 고름 |
| 반응 조절 | 선택지를 천천히 확인하고 최종 답변 |

---

## 2. 다중 실행 모드 아키텍처

동일한 게임 로직을 유지하되 앱 또는 허브 페이지가 전달하는 runtime config에 따라 화면 구성과 조작 난이도를 제어합니다.

| 모드 | 목적 | 주요 UI 정책 |
|---|---|---|
| `standard` | 사용자가 직접 진입하는 일반 플레이 | 난이도 선택, 타이머, 점수, 설정, 진행방법, 컨디션 체크 노출 |
| `reminder` | 보호자/앱 알림을 통한 짧은 진입 | 앱 지정값으로 즉시 시작, 난이도 선택/설정/컨디션 체크 숨김 |
| `care` | 요양기관/데이케어/돌봄기관 환경 | 타이머, 점수, 난이도 선택, 설정 등 복잡한 UI 숨김. 케어 전용 10문항 흐름 적용 |
| `ai_assisted` | 앱 또는 AI 대화 시스템 보조 입력 연동 | 난이도 선택과 컨디션 체크 숨김, 외부 답변 입력 확장 가능 |

## 3. 실행 모드별 파라미터 호출 규격

| 호출 모드 | 진입 경로 특징 | 필수/권장 config | 시니어 접근성 UI 제어 상태 |
|---|---|---|---|
| `standard` | B2C 시니어 직접 진입 | `show_difficulty_select: true`, `show_timer: true`, `show_score: true` | 사용자가 난이도를 직접 선택하고 전체 UI를 사용 |
| `reminder` | 보호자 예약 알림 수신 | `show_difficulty_select: false`, `show_condition_check: false` | 앱이 지정한 값으로 바로 시작 |
| `care` | 돌봄기관/데이케어 복지 환경 | `show_difficulty_select: false`, `show_timer: false`, `show_score: false`, `show_settings: false` | 중앙 과제에 집중하는 Clean HUD 적용 |
| `ai_assisted` | AI 대화/음성 보조 연동 | `show_condition_check: false`, `voice_guide_enabled: true`, `result_log_level: "detailed"` | 앱/AI가 전달한 외부 입력을 받을 수 있는 구조 |

## 4. Runtime Config 수신 우선순위

현재 구현 기준 `app-bridge.js`는 아래 순서로 실행 config를 찾습니다.

| 우선순위 | 방식 | 설명 |
|---:|---|---|
| 1 | `window.__GAME_CONFIG__` | 실제 앱/WebView가 직접 주입하는 권장 방식 |
| 2 | `window.GAME_CONFIG` | 보조 전역 config |
| 3 | `sessionStorage` | 개발용 허브가 저장한 config |
| 4 | `config/<mode>.config.json` fetch | URL의 `mode` 값을 기준으로 config 파일 로드 |
| 5 | 기본 mock config | 아무 config도 없을 때의 안전 기본값 |

개발용 허브의 저장 키는 아래와 같습니다.

```text
fruit-count-memory-game:runtime-config:v2
```

## 5. 진입 URL 규격

| 모드 | 개발/배포 진입 URL |
|---|---|
| 표준 모드 | `games/fruit-count-memory-game/index.html?mode=standard` |
| 알림 모드 | `games/fruit-count-memory-game/index.html?mode=reminder` |
| 케어 모드 | `games/fruit-count-memory-game/index.html?mode=care` |
| AI 연동 모드 | `games/fruit-count-memory-game/index.html?mode=ai_assisted` |

URL의 `mode` 값은 어떤 모드로 실행할지 알려주는 최소 진입값입니다. 실제 문항 수, 힌트, 타이머 표시 여부 등은 runtime config JSON이 최종 결정합니다.

## 6. 기본 진입값

서비스 명세상 기본 진입값은 아래와 같이 정의합니다.

```json
{
  "session_id": "game_session_3001",
  "content_id": "cognitive_count_fruit_001",
  "game_key": "counting_fruits",
  "mode": "care",
  "difficulty": null
}
```

케어 모드에서는 난이도 선택을 사용자에게 노출하지 않으며, `difficulty`를 서비스 정책 분기값으로 사용하지 않습니다. 현재 구현은 내부 호환을 위해 난이도 인덱스 0을 기본 시작점으로 사용할 수 있지만, 운영 문서에서는 케어를 단일 `care` 정책으로 관리합니다.

현재 코드에서 직접 사용하는 런타임 필드는 camelCase 기준입니다.

| 서비스 명세 필드 | 현재 코드 기준 필드 | 설명 |
|---|---|---|
| `session_id` | `sessionId` | 1회 게임 실행 세션 ID |
| `content_id` | `contentId` | 콘텐츠 식별자 |
| `game_key` | `gameKey` | 서비스 카탈로그용 게임 키 |
| `game_id` | `gameId` | 구현/브릿지 기준 게임 ID |
| `mode` | `mode` | 실행 모드 |
| `difficulty` | `difficulty` 또는 `difficultyKey` | 케어 모드에서는 운영상 사용하지 않음 |

## 8. Config 항목 설명

| 항목 | 타입 | 설명 |
|---|---|---|
| `mode` | string | 실행 모드. `standard`, `reminder`, `care`, `ai_assisted` 중 하나 |
| `difficulty` | string/null | 시작 난이도. 케어 모드에서는 운영상 사용하지 않음 |
| `show_timer` | boolean | 화면에 남은 시간을 보여줄지 여부 |
| `show_score` | boolean | 점수/진행 상태 UI 노출 여부 |
| `show_difficulty_select` | boolean | 시작 전 난이도 선택 화면 노출 여부 |
| `show_settings` | boolean | 설정 버튼 노출 여부 |
| `show_how_to_play` | boolean | 진행방법 버튼/도움말 노출 여부 |
| `show_condition_check` | boolean | 시작 전 컨디션 체크 노출 여부 |
| `show_finish_check` | boolean | 종료 후 소감/상태 체크 노출 여부 |
| `duration_seconds` | number | 게임 제한 시간. UI에서 숨겨도 내부 안전 제한값으로 사용 가능 |
| `reveal_ms` | number | 기억 단계에서 과일을 보여주는 시간(ms) |
| `question_count` | number | 총 문항 수 |
| `choice_count` | number | 답변 선택지 수 |
| `max_items_to_remember` | number | 기억해야 하는 과일 총 개수 상한 |
| `hint_enabled` | boolean | 힌트 사용 가능 여부 |
| `auto_hint_enabled` | boolean | 오답 또는 지연 시 자동 힌트 정책 활성화 여부 |
| `soft_feedback` | boolean | 부드러운 피드백 문구 사용 여부 |
| `voice_guide_enabled` | boolean | 음성 안내 사용 여부 |
| `result_log_level` | string | 결과 로그 상세 수준 |

## 11. 케어 모드 전용 UX/난이도 명세

케어 모드는 난이도 선택형 모드가 아니라, 돌봄 환경에서 바로 사용할 수 있는 단일 과제 흐름입니다.

### 11.1 화면 구성

- 상단 헤더, 타이머, 점수, 난이도 선택, 설정, 진행방법 버튼을 숨깁니다.
- 기억해야 하는 과일 이미지를 화면 중앙에 크게 표시합니다.
- 답변 버튼은 크고 간격이 넓은 한글 선택지로 표시합니다.
- 남은 시간, 카운트다운, 점수 경쟁처럼 압박을 주는 표현은 노출하지 않습니다.
- 반응 시간은 UI에 표시하지 않고 내부 로그로만 기록합니다.

### 11.2 케어 모드 문항 흐름

| 단계 | 화면/문구 예시 | 설명 |
|---|---|---|
| 제시 | `포도가 몇 개 있는지 같이 봐볼까요?` | 과일 이미지를 크게 보여줌. 선택지는 숨김 |
| 전환/가림 | `좋아요. 이제 한 번 떠올려볼까요?` | 과일을 숨기고 답변 단계로 전환 |
| 답변 | `방금 포도가 몇 개 있었을까요?` | 한글 선택지로 답변 |

답변 선택지는 숫자보다 쉬운 한글 표현을 사용합니다.

| 값 | 표시 문구 |
|---:|---|
| 1 | 하나 |
| 2 | 두 개 |
| 3 | 세 개 |
| 4 | 네 개 |
| 5 | 다섯 개 |

### 11.3 케어 모드 문항 생성 규칙

| 문항 | 과일 종류 | 총 개수 | 선택지 수 | 설명 |
|---:|---:|---:|---:|---|
| 1-2 | 1종류 | 1-2개 | 2개 | 아주 쉬운 시작 |
| 3 | 1종류 | 1-3개 | 2개 | 선택 부담 유지 |
| 4-6 | 1종류 | 1-3개 | 3개 | 같은 유형 안에서 선택지 증가 |
| 7-8 | 2종류 | 총 4개 | 3개 | 두 과일이 섞이기 시작 |
| 9-10 | 2종류 | 총 5개 | 3개 | 최대 5개까지만 제시 |

세부 규칙은 아래와 같습니다.

- 케어 모드 최대 과일 개수는 `max_items_to_remember`와 5 중 작은 값으로 제한합니다.
- 1-6번 문항은 한 종류의 과일만 보여줍니다.
- 7-10번 문항은 두 종류의 과일만 섞습니다.
- 7-8번 문항은 총 4개, 9-10번 문항은 총 5개로 제한합니다.
- 목표 과일은 제시된 과일 중 하나를 무작위로 선택합니다.
- 선택지는 정답 주변 값으로 구성하되, 정답은 반드시 포함합니다.

### 11.4 케어 모드 피드백 원칙

| 상황 | 피해야 할 표현 | 권장 표현 |
|---|---|---|
| 오답 | `틀렸어요` | `조금 헷갈릴 수 있어요. 다시 한 번 볼까요?` |
| 재시도 | `실패` | `괜찮아요. 천천히 다시 떠올려볼게요.` |
| 정답 | 과장된 칭찬 | `잘 확인해주셨어요.` |
| 완료 | 점수 경쟁 강조 | `끝까지 차분히 진행했어요.` |

## 13. 앱 브릿지 이벤트

현재 브릿지는 mock 형태로 콘솔에 이벤트를 출력합니다. 실제 앱 연동 시 동일한 payload를 네이티브 브릿지로 전달하면 됩니다.

| 이벤트 | 전송 시점 | 설명 |
|---|---|---|
| `GAME_READY` | config 적용 및 에셋 준비 후 | 게임 실행 준비 완료 |
| `GAME_STARTED` | 실제 게임 시작 시 | 세션 시작 로그 |
| `GAME_COMPLETED` | 모든 문항 완료 후 | 결과 상세 로그 |

## 21. AI 연동 입력 확장안

AI 연동 모드에서는 WebView가 마이크 권한이나 STT를 직접 처리하지 않는 것을 원칙으로 합니다. 앱 또는 AI 레이어가 음성 인식 결과를 텍스트/값으로 변환한 뒤 게임에 전달합니다.

권장 메시지 형식은 아래와 같습니다.

```json
{
  "type": "EXTERNAL_ANSWER",
  "payload": {
    "sessionId": "game_session_3001",
    "questionInstanceId": "q_001",
    "inputType": "voice",
    "selectedAnswer": 2,
    "rawTranscript": "두 개",
    "confidence": 0.86,
    "receivedAt": "2026-05-29T04:19:30.000Z"
  }
}
```

처리 규칙:

- `selectedAnswer`가 숫자로 명확하면 해당 선택지를 누른 것과 동일하게 처리합니다.
- `rawTranscript`만 있을 경우 `하나`, `한 개`, `두 개`, `셋`, `세 개` 등 한국어 수량 표현을 숫자로 변환합니다.
- `confidence`가 낮으면 바로 오답 처리하지 않고 다시 확인하는 문구를 보여줍니다.
- AI 입력은 터치 입력과 동일하게 `questionResults`, `processData`에 기록합니다.

## 22. 앱 개발팀 전달용 핵심 규칙

1. 앱은 WebView 로드 전에 모드별 JSON config를 준비합니다.
2. 실제 연동에서는 `window.__GAME_CONFIG__`에 config를 주입하는 방식을 우선 권장합니다.
3. 게임은 URL의 `mode`만으로 모든 정책을 결정하지 않습니다. 최종 정책은 runtime config가 결정합니다.
4. 케어 모드는 단일 `care` 정책으로 관리하며, 케어 내부 난이도 분기는 운영 문서에 만들지 않습니다.
5. 케어 모드에서는 타이머와 점수를 숨기지만 반응 시간은 내부 로그로 기록합니다.
6. 완료 시 앱은 `GAME_COMPLETED` payload를 수신해 서버 저장 또는 결과 화면 처리에 사용합니다.
7. 오류 시 앱은 `GAME_ERROR`를 수신해 재시도, 앱 복귀, 디버그 로그 저장 정책을 적용합니다.

## 23. 구현 상태와 추가 필요 사항

| 항목 | 현재 상태 | 추가 필요 여부 |
|---|---|---|
| 모드별 config JSON | 구현됨 | 운영값 확정 필요 |
| 허브에서 모드별 config 전달 | 구현됨 | 실제 앱에서는 네이티브 주입 방식으로 대체 |

| 케어 모드 전용 UI 숨김 | 구현됨 | 현장 QA 필요 |
| 케어 모드 전용 문항 생성 | 구현됨 | 현장 테스트 후 값 조정 가능 |

| `touch_miss_count` | 미구현 | 필요 시 터치 로그 구현 |
| `changed_answer_count` | 미구현 | 필요 시 답변 변경 로그 구현 |
| `difficulty_downshifted` | 미구현 | 케어 단일 정책에서는 기본 미사용 |
