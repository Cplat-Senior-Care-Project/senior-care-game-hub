오늘의 준비물 README / 실행 가이드

작성 기준: what-fits-where 폴더의 실제 실행 구조와 index.html, config/modes.js, js/game.js, modes/registry.js에서 확인되는 게임 흐름을 기준으로 정리했습니다.

1. 개요

오늘의 준비물은 WebView 기반 일상생활 판단 활동 게임입니다. 사용자는 병원 방문, 장보기, 비 오는 날 외출처럼 익숙한 상황 문장을 보고, 그 상황에 필요한 물건을 고릅니다.

현재 기본 미션은 알맞은 물건 고르기입니다. 게임 엔진에는 아래 세 가지 미션 타입이 등록되어 있습니다.

미션 타입화면 표시명설명현재 사용 상태
choose_matching_items알맞은 물건 고르기상황에 맞는 필요한 물건을 고릅니다.현재 기본 사용
remove_mismatched_items어울리지 않는 물건 고르기상황에 어울리지 않는 물건을 고릅니다.엔진 등록
guess_situation상황 맞추기제시된 물건들을 보고 알맞은 상황을 고릅니다.엔진 등록
문제 데이터는 docs/situation-templates-draft.json을 우선 불러오고, 로드에 실패하면 js/situation-templates.js의 내장 데이터와 js/questions.js의 기본 문제 풀이 fallback으로 사용됩니다.

2. 지원 모드

앱 모드용도주요 동작
standard기본 실행 모드컨디션 체크, 난이도 선택, 설정, 게임 방법, 점수 화면, 게임 후 상태 체크를 제공합니다.
reminder알림 진입 모드기본 난이도로 자동 시작하고, 완료 후 효담콜로 자동 복귀합니다.
care케어 모드기본 쉬움 난이도와 짧은 문항 수로 실행하며, 자동 힌트와 자동 복귀를 사용합니다.
ai_assistedAI 연동 진입용 모드현재 게임 내부에서 STT나 AI 판정은 직접 수행하지 않으며, care와 유사한 UI/진행 설정을 사용합니다.

8. Config 수정 방법

기본 config는 config/modes.js 파일에서 수정합니다. 모드별 기본값은 modeConfigs에 정의되어 있고, 공통 기본값은 DEFAULT_CONFIG에 정의되어 있습니다.

항목예시 값설명
window.GAME_MODEcare실행할 앱 모드
window.HUB_RETURN_URL../../index.html효담콜 복귀 주소
window.USER_DIFFICULTY_GROUPlow사용자 난이도 그룹
window.GAME_CONFIG별도 객체화면 표시 여부, 기본 난이도, 자동 시작/복귀 등을 담는 설정 객체
현재 구현은 window.GAME_CONFIG를 사용합니다. 전구 게임 예시의 window.__GAME_CONFIG__ 또는 runtimeConfig 형태를 그대로 읽는 코드는 아직 없습니다. 호스트 앱이 __GAME_CONFIG__를 사용한다면 게임 로드 전에 window.GAME_CONFIG 형태로 변환해 주입해야 합니다.

12. 앱 / WebView 연동 구조

게임은 주요 진행 상태를 호스트 앱에 이벤트로 전달합니다. React Native WebView 환경에서는 window.ReactNativeWebView.postMessage를 우선 사용합니다. 로컬 브라우저처럼 브리지가 없는 환경에서는 콘솔에 Game Event 형태로 출력됩니다.

이벤트 타입발생 시점전달 내용
GAME_READY로딩 완료기본 이벤트 정보
GAME_STARTED게임 시작미션 모드, 난이도
HINT_OPENED수동 또는 자동 힌트 열림미션 모드, 문항 번호, 힌트 트리거
GAME_RESTARTED일시정지 메뉴에서 다시하기 선택미션 모드, 난이도
GAME_ERROR게임 로드 또는 실행 오류오류 메시지
GAME_COMPLETED완료, 시간 종료, 사용자 중단전체 결과 payload
POST_GAME_CONDITION_COMPLETED게임 후 상태 체크 완료게임 후 상태 체크 응답
POST_GAME_CONDITION_SKIPPED게임 후 상태 체크 건너뛰기건너뛰기 여부
RETURN_TO_HUB효담콜 복귀 요청앱 모드
현재 구현에서는 사용자 중단도 별도 GAME_ABANDONED 이벤트가 아니라 GAME_COMPLETED 이벤트 안에서 status 값을 abandoned로 전달합니다.

14. AI 연동 모드

항목현재 동작
컨디션 체크숨김
기본 난이도easy
문항 수난이도별 5문항
힌트 버튼사용
자동 힌트20초 후 열림
완료 후 동작효담콜 자동 복귀
현재 게임 내부에는 마이크 권한 요청, STT 처리, AI 판정, 외부 답변 적용 이벤트 리스너가 구현되어 있지 않습니다. 따라서 AI가 음성 인식 결과를 선택값으로 변환하더라도, 현재 코드 기준으로는 게임에 자동 반영되지 않습니다.
단계담당구현 내용
1호스트 앱 또는 AI 레이어음성을 인식합니다.
2호스트 앱 또는 AI 레이어인식 결과를 물건 선택값으로 변환합니다.
3게임window.postMessage 또는 전용 브리지 이벤트 리스너를 추가합니다.
4게임수신한 선택값을 현재 문제의 물건 버튼 클릭과 동일하게 처리합니다.

17. 주의사항

항목주의 내용
Config 주입 순서config/modes.js는 index.html 하단에서 가장 먼저 로드됩니다. WebView에서 전역 config를 주입하려면 이 스크립트보다 먼저 적용되어야 합니다.
JSON 로드docs/situation-templates-draft.json은 서버 환경에서 fetch됩니다. 직접 파일 열기보다 정적 서버 실행을 권장합니다.
안내 음성voice_guide_enabled는 안내 음성 재생 여부만 제어하며, AI 음성 인식 기능을 의미하지 않습니다.
AI 모드ai_assisted 모드는 이름상 AI 연동용이지만, 현재 구현은 UI/진행 설정만 제공합니다.
자동 복귀care와 ai_assisted는 자동 복귀가 켜져 있으므로 결과 화면이 약 1.2초 표시된 뒤 효담콜 복귀가 요청됩니다.
모드 구조모드별 폴더가 따로 있는 구조가 아니라, 단일 index.html과 query parameter/config 조합으로 모드를 전환합니다.
