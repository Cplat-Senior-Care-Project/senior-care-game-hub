# 오늘의 준비물 - 게임 결과 데이터 정의서

본 문서는 `오늘의 준비물` WebView 게임이 종료될 때, 호스트 앱(React Native WebView 등)으로 전송하는 **결과 Payload(JSON) 및 상세 필드 규격**을 정리한 정의서입니다.

---

## 1. 전송 시점 및 수신 방법

* **전송 시점**: 게임 플레이가 완료(정상 종료, 강제 종료, 시간 초과)되면 `finishGame()` 함수를 통해 최종 결과 데이터가 생성되어 전송됩니다.
* **수신 방법**:
  * React Native WebView 환경: `window.ReactNativeWebView.postMessage(JSON.stringify(message))`를 통해 메시지를 수신합니다.
  * 로컬 브라우저 디버깅: 브라우저 콘솔(`console.log("GAME_RESULT", result)`)에 직접 출력됩니다.

---

## 3. 세부 필드 명세

### 3-1. 공통 메타데이터 필드 (루트 수준)

| 필드명 | 타입 | 필수여부 | 설명 |
| :--- | :---: | :---: | :--- |
| `senior_id` | String | 필수 | 대상 시니어 회원 고유 ID (호스트 앱 연동) |
| `guardian_id` | String | Nullable | 보호자 ID |
| `content_id` | String | 필수 | 콘텐츠 ID (`content_what_fits_where`) |
| `game_key` | String | 필수 | 게임의 내부 식별용 고유 키 (`what_fits_where`) |
| `game_version` | String | 필수 | 게임 릴리즈 버전 (예: `1.0.0`) |
| `session_id` | String | 필수 | 1회 실행 단위 식별 세션 ID (중복 저장 방지 키) |
| `play_source` | String | 필수 | 진입 채널 (`reminder` \| `manual` \| `care_session` 등) |
| `status` | String | 필수 | **진행 결과 상태**: `completed` (완료) \| `abandoned` (중단) |
| `exit_reason` | String | 필수 | **세부 종료 사유**: `completed` \| `user_exit` (스스로 나가기) \| `time_over` (시간 초과) |
| `started_at` | String | 필수 | 게임 시작 일시 (ISO 8601 UTC) |
| `ended_at` | String | 필수 | 게임 종료/중단 일시 (ISO 8601 UTC) |
| `duration_ms` | Integer | 필수 | 총 플레이 시간 (밀리초 단위) |
| `duration_sec` | Integer | 필수 | 총 플레이 시간 (초 단위) |

### 3-2. 수행 수치 통계 필드

| 필드명 | 타입 | 설명 |
| :--- | :---: | :--- |
| `total_questions` | Integer | 세션에 출제된 총 문항 수 (표준 10개 / 케어 5개) |
| `answered_questions` | Integer | 최종 답변 처리된 문항 수 |
| `correct_count` | Integer | 정답 문항 수 (최종 정답 선택 완료) |
| `wrong_count` | Integer | 오답 문항 수 (오답 3회 이상으로 자동 공개된 경우 등) |
| `accuracy_percent` | Integer | 정답률 (0 ~ 100) |
| `completion_rate` | Float | 문항 이수율 (0.0000 ~ 1.0000) |
| `hint_count` | Integer | 게임 전체에서 사용한 수동/자동 힌트 총 개수 |
| `retry_count` | Integer | 오답 선택 후 다시 시도한 오답 터치 횟수 |
| `avg_response_sec` | Float | 평균 문항 답변 시간 (초) |

### 3-3. 문항별 세부 로그 (`question_logs` 배열 내부)

각 문항이 끝날 때마다 기록되는 세부 동작 객체의 배열 스키마입니다.

| 필드명 | 타입 | 설명 |
| :--- | :---: | :--- |
| `question_index` | Integer | 문항 번호 (1부터 시작) |
| `stage` | Integer | 단계 번호 (기본 1) |
| `game_mode` | String | 미션 유형 (`choose_matching_items`) |
| `situation` | String | 화면에 제시된 질문/상황 텍스트 |
| `item_keys` | Array | 문항에 제공된 선택지 물건들의 고유 키 배열 |
| `item_names` | Array | 문항에 제공된 선택지 물건들의 한글 이름 배열 |
| `answer_keys` | Array | 해당 질문의 정답 물건 고유 키 배열 |
| `answer_names` | Array | 해당 질문의 정답 물건 한글 이름 배열 |
| `selected_keys` | Array | 사용자가 최종 선택한 물건들의 고유 키 배열 |
| `correct` | Boolean | 정답 처리 여부 (`true` \| `false`) |
| `response_ms` | Integer | 해당 문항 풀이에 걸린 시간 (밀리초) |
| `hint_count` | Integer | 해당 문항에서 열어본 힌트 횟수 |
| `retry_count` | Integer | 해당 문항에서 발생한 오답 횟수 |
| `attempts` | Array | **문항 상세 응답 타임라인**: <br> 각 터치 시점의 경과 시간(`elapsed_ms`), 선택 물건(`item_key`), 정오답 여부(`correct`) 로그 기록 |

### 3-4. 상세 부가 정보 (`result_detail_json`)

* **`condition_data`**: 게임 시작 전 컨디션 체크 결과 (`mood`, `sleep_hours`, `skipped`)
* **`post_game_condition_data`**: 게임 완료 후 평가 피드백 결과
  * `mood`: 게임 종료 후 기분
  * `difficulty_feel`: 사용자가 느낀 난이도 체감 (`easy` \| `justRight` \| `hard`)
  * `fatigue`: 게임 후 피로감 (`low` \| `medium` \| `high`)
  * `needed_help`: 타인의 도움 필요 여부 (`some` \| `none`)
  * `want_replay`: 재참여 의사 (`yes` \| `no`)
* **`recommended_next_difficulty`**: 맞춤형 추천 다음 난이도 (`easy` \| `normal` \| `hard`)
