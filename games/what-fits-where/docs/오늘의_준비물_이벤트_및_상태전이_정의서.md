# 오늘의 준비물 이벤트 및 상태전이 정의서

## 1. 문서 개요

이 문서는 `오늘의 준비물` 게임의 모든 주요 상태(State)와 상태 간 전이(Transition), 앱-게임 연동 이벤트를 정의한다. Cplat 개발팀이 게임 클라이언트 구현, 효담콜 앱 연동, 케어/AI 보조 모드 진입 정책을 확인할 때 참조하는 기준 문서다.

현재 활성 게임 유형은 `알맞은 물건 고르기`이며 내부 미션 키는 `choose_matching_items`다. 과거 구조의 `remove_mismatched_items`, `guess_situation` 코드는 일부 남아 있으나, 현재 설정의 미션 시퀀스에는 포함되지 않는다.

### 참조 문서 및 구현 파일

## 2. 상태 목록

게임 내 존재하는 상태는 화면 단위가 아니라 게임 로직 단위로 정의한다. 일부 상태는 동일 화면 위의 모달 또는 내부 플래그로 표현된다.

| 상태 ID | 상태명 | 구현 기준 | 설명 |
|---|---|---|---|
| S-00 | LOADING | `loading-screen.active` | 리소스와 상황 템플릿을 준비하는 초기 상태 |
| S-01 | CONDITION_CHECK | `screen-condition` | 게임 전 기분과 수면시간을 확인하는 상태 |
| S-02 | START | `screen-start` | 타이틀, 시작, 설정, 게임 방법, 앱 복귀 진입 상태 |
| S-03 | TUTORIAL | `help-modal.active` | 게임 방법 안내 모달 상태 |
| S-04 | DIFFICULTY_SELECT | `screen-difficulty` | 표준 모드에서 난이도를 선택하는 상태 |
| S-05 | COUNTDOWN | `countdown-modal.active` | 게임 시작 직전 3초 카운트다운 상태 |

| S-08 | FEEDBACK | `p-feedback` 표시 또는 `reveal-modal.active` | 정오답 피드백, 정답 공개, 다음 문항 대기 상태 |
| S-09 | PAUSED | `pause-modal.active`, `state.paused=true` | 일시정지 메뉴 상태 |
| S-10 | EXIT_CONFIRM | `exit-modal.active` | 게임 종료 의사를 확인하는 상태 |

| S-12 | RESULT | `screen-result` | 활동 완료 메시지와 다음 행동을 보여주는 상태 |
| S-13 | SCORE | `screen-score` | 표준 모드 점수 확인 상태 |
| S-14 | POST_GAME_CHECK_1 | `screen-post-check-1` | 게임 후 기분, 난이도 체감, 피로감 확인 상태 |
| S-15 | POST_GAME_CHECK_2 | `screen-post-check-2` | 도움 필요 여부와 재시도 의향 확인 상태 |
| S-16 | ERROR | `error-modal.active` | 예외 또는 데이터 로드 실패 표시 상태 |
| S-17 | RETURN_TO_APP | `returnToHub()` | 효담콜 또는 호출 앱으로 복귀하는 종료 상태 |

## 4. 이벤트 명세

게임-앱 간 `postMessage` 이벤트 목록이다. 현재 구현은 게임에서 앱으로 보내는 상태 이벤트와 앱에서 게임으로 보내는 config/일시정지/외부 선택 이벤트를 모두 처리한다.

### 4-1. 게임 -> 앱

공통 이벤트 래퍼는 다음 형식이다.

```js
{
  type: "EVENT_NAME",
  payload: {},
  timestamp: "2026-06-15T00:00:00.000Z"
}
```

React Native WebView 환경에서는 `window.ReactNativeWebView.postMessage(JSON.stringify(message))`를 사용한다. 로컬 브라우저에서는 `console.log("Game Event:", message)`로 출력한다.

| 이벤트명 | 발생 시점 | 주요 payload | 비고 |
|---|---|---|---|
| `GAME_READY` | 로딩 완료 | `session_id`, `mode`, `difficulty`, `config_snapshot` | 로딩 바 100% 후 송신 |
| `GAME_STARTED` | 카운트다운 완료 후 첫 문항 시작 | `session_id`, `mode`, `game_mode`, `difficulty`, `started_at`, `config_snapshot` | `mode`는 앱 진입 모드, `game_mode`는 현재 `choose_matching_items` |
| `HINT_OPENED` | 수동/자동 힌트 열림 | `mode`, `question_index`, `trigger` | `trigger`는 `manual` 또는 `auto` |
| `GAME_RESTARTED` | 일시정지 메뉴에서 다시하기 | `mode`, `difficulty` | 새 게임 시작 직전 송신 |
| `CONFIG_APPLIED` | 앱 config 적용 | `session_id`, `mode`, `difficulty`, `config_snapshot` | URL, `postMessage`, 직접 호출 모두 같은 구조 |
| `GAME_ERROR` | 오류 모달 표시 | `status=error`, `message`, `config_snapshot` | 전역 JS 오류 또는 데이터 로드 실패 |
| `GAME_COMPLETED` | 정상 완료 | 결과 payload 전체 | `status=completed` |
| `GAME_ABANDONED` | 사용자 중단, 시간 종료 | 결과 payload 전체 | `status=abandoned`, `exit_reason`으로 사유 구분 |
| `POST_GAME_CONDITION_COMPLETED` | 게임 후 상태 체크 완료 | 사후 상태 체크 값 | 표준 모드에서 사용 |
| `POST_GAME_CONDITION_SKIPPED` | 게임 후 상태 체크 건너뜀 | `skipped=true`, 각 응답값 `null` | 표준 모드에서 사용 |
| `RETURN_TO_HUB` | 효담콜 복귀 요청 | `app_mode`, `mode`, `session_id` | 복귀 URL 이동 전 송신 |

로컬 브라우저에서는 디버깅 편의를 위해 `console.log("GAME_RESULT", result)`도 출력한다. React Native WebView에는 이벤트 래퍼 메시지를 기준으로 한 번만 전송한다.

`returnToHub()`는 호환 목적으로 래퍼 이벤트 외에 아래 메시지도 직접 송신한다.

```js
{ type: "RETURN_TO_HUB", app_mode: "care", mode: "care", session_id: "..." }
{ type: "RETURN_TO_HYODAM_CALL", app_mode: "care", mode: "care", session_id: "..." }
```

### 4-2. 앱 -> 게임

앱에서 게임으로 들어오는 `message`/`postMessage` 이벤트와 직접 호출 API는 아래와 같다.

| 이벤트명 | 현재 지원 여부 | 설명 |
|---|---|---|
| `APP_CONFIG` / `GAME_CONFIG` / `CONFIG` | 지원 | `session_id`, `content_id`, `mode`, `difficulty`, `config` 등을 적용한다. |
| `EXTERNAL_ANSWER` | 지원 | `item_key`, `key`, `answer`, `label`, `text` 중 전달된 값으로 현재 선택지를 누른다. |
| `EXTERNAL_ITEM_SELECT` | 지원 | `EXTERNAL_ANSWER`와 같은 방식으로 처리한다. |
| `PAUSE_GAME` / `RESUME_GAME` | 지원 | 앱에서 게임 타이머와 응답 시간 기록을 일시정지/재개할 수 있다. |
| `window.applyGameRuntimeConfig(payload)` | 지원 | postMessage 없이 직접 config를 적용하는 함수다. |

앱은 대신 URL 파라미터 또는 전역 설정값으로 진입 모드와 난이도 정책을 전달한다.

| 입력 방식 | 값 | 설명 |
|---|---|---|
| URL `mode` | `standard`, `reminder`, `care`, `ai_assisted` | 앱 진입 모드 |
| URL `mode=ai-assisted` | 내부에서 `ai_assisted`로 변환 | 하이픈 별칭 지원 |
| URL `userDifficultyGroup` | `low`, `middle`, `high` | 각각 `easy`, `normal`, `hard`로 매핑 |
| URL `returnUrl` | 상대/절대 URL | 복귀 시 이동할 주소 |
| URL `config`, `gameConfig`, `appConfig` | JSON 문자열 | 앱 설정 객체를 URL로 전달 |
| URL `session_id`, `content_id`, `game_key` | 문자열 | 결과 저장 식별자 |
| `window.GAME_CONFIG` | 설정 객체 | 문항 수, UI 노출, 기본 난이도 등 오버라이드 |
| `window.GAME_MODE` | 앱 모드 문자열 | URL보다 우선 적용 가능 |
| `window.USER_DIFFICULTY_GROUP` | `low`, `middle`, `high` | 프로필 기반 난이도 |
| `window.HUB_RETURN_URL` | URL 문자열 | 복귀 주소 |

## 5. 모드별 분기 요약

여기서 모드는 게임 유형이 아니라 앱 진입 방식이다. 모든 앱 모드에서 현재 실제 게임 유형은 `알맞은 물건 고르기`다.

### 5-1. 상태 노출 여부

| 상태 | `standard` | `reminder` | `care` | `ai_assisted` |
|---|---:|---:|---:|---:|
| LOADING | O | O | O | O |
| CONDITION_CHECK | O | 설정 시 O | X | X |
| START | O | O, 기본 설정은 자동 시작 | O | O |
| TUTORIAL | O | 기본 X, 설정 시 O | 기본 X, 설정 시 O | 기본 X, 설정 시 O |
| DIFFICULTY_SELECT | O | X | X | X |
| COUNTDOWN | O | O | O | O |
| ANSWER | O | O | O | O |
| HINT | O | O | O | O |
| PAUSED | O | 설정 시 O | 기본 X, 앱 메시지 지원 | 기본 X, 앱 메시지 지원 |
| RESULT | O | O | O | O |
| SCORE | O | X | X | X |
| POST_GAME_CHECK_1/2 | O | X | X | X |
| RETURN_TO_APP | 수동 | 자동/수동 | 자동/수동 | 자동/수동 |

### 5-2. 문항 수 및 타이머

| 모드 | 기본 난이도 | 문항 수 | 제한시간 | 난이도 선택 |
|---|---|---:|---:|---|
| `standard` | 사용자 선택 | 10문항 | 180초 | 사용 |
| `reminder` | `easy` | 10문항 | 180초 | 생략 |
| `care` | `easy` | 5문항 | 180초, 화면 타이머 기본 숨김 | 생략 |
| `ai_assisted` | `easy` | 5문항 | 180초, 화면 타이머 기본 숨김 | 생략 |

난이도별 선택지 구성은 다음과 같다.

| 난이도 | 선택지 수 | 정답 수 |
|---|---:|---:|
| `easy` | 2개 | 1개 |
| `normal` | 3개 | 2개 |
| `hard` | 4개 | 2개, 뒤쪽 일부 문항은 3개 |

### 5-3. 결과 화면 및 복귀 방식

| 모드 | RESULT 버튼 | SCORE | 사후 상태 체크 | 자동 복귀 |
|---|---|---|---|---|
| `standard` | `다시 하기`, `다음` | O | O | X |
| `reminder` | `효담콜로 돌아가기` | X | X | O |
| `care` | `효담콜로 돌아가기` | X | X | O |
| `ai_assisted` | `효담콜로 돌아가기` | X | X | O |

### 5-4. 힌트 동작

| 모드 | 수동 힌트 | 자동 힌트 | 자동 힌트 조건 |
|---|---:|---:|---|
| `standard` | O | X | 없음 |
| `reminder` | O | X | 없음 |
| `care` | O | O | 문항 시작 후 20초 동안 진행 없음 |
| `ai_assisted` | O | O | 문항 시작 후 20초 동안 진행 없음 |

힌트가 열리면 `state.paused=true`가 되며 타이머 감소와 선택 처리가 멈춘다. 힌트를 닫으면 힌트 열기 전 상태가 일시정지가 아니었던 경우에만 풀이 상태로 복귀한다.

### 5-5. 피드백 분기

현재 활성 미션 `choose_matching_items`의 피드백 규칙은 다음과 같다.

| 입력 | 조건 | 피드백 | 결과 처리 |
|---|---|---|---|
| 정답 선택 | 아직 고르지 않은 정답 | 칭찬 메시지, 선택 표시 | 모든 정답을 고르면 문항 정답 처리 |
| 오답 선택 | 오답 1회 | 재시도 안내, 흔들림 효과 | 같은 문항 계속 진행 |
| 오답 선택 | 오답 2회 이상 | 정답 공개 모달 | 문항 오답 처리 후 다음 문항 |
| 제한시간 종료 | `timerLeft <= 0` | 결과 화면 | 전체 게임 `status=abandoned`, `exit_reason=time_over` 처리 |
| 사용자 종료 | 종료 확인에서 그만하기 | 결과 화면 | 전체 게임 `abandoned` 처리 |

## 6. 결과 payload 주요 필드

`GAME_COMPLETED`와 `GAME_ABANDONED`의 payload는 아래 필드를 포함한다.

| 필드 | 설명 |
|---|---|
| `session_id`, `content_id`, `game_key`, `game_version` | 앱/API 저장용 식별자 |
| `mode`, `app_mode` | 앱 진입 모드 `standard`, `reminder`, `care`, `ai_assisted` |
| `game_mode`, `mission_mode` | 현재 게임 유형. 현재는 `choose_matching_items` |
| `game_mode_label` | 화면 표시명. 현재는 `알맞은 물건 고르기` |
| `cognitive_areas` | 인지 영역 배열 |
| `difficulty`, `start_difficulty` | 시작 난이도 `easy`, `normal`, `hard` |
| `difficulty_label` | `쉬움`, `보통`, `어려움` |
| `difficulty_source` | `user_selected`, `profile_based`, `care_default`, `{mode}_default` 등 |
| `config_snapshot` | 실제 적용된 config와 fallback/default 값 |
| `total_stages` | 전체 단계 수. 현재 기본 1 |
| `questions_per_stage` | 단계별 문항 수 배열 |
| `total_questions` | 전체 문항 수 |
| `answered_questions` | 정답/오답으로 처리된 문항 수 |
| `correct_count` | 정답 문항 수 |
| `wrong_count` | 오답 문항 수 |
| `hint_count`, `retry_count` | 힌트 사용 수와 재시도 수 |
| `question_logs` | 문항별 상황, 선택, 정답, 응답 시간, 상태 로그 |
| `accuracy_percent` | 정답률 |
| `avg_response_sec` | 평균 문항 응답 시간 |
| `started_at`, `ended_at`, `duration_ms` | 실행 시작/종료 시각과 총 소요 시간 |
| `duration_sec` | 전체 게임 진행 시간 |
| `completed` | 정상 완료 여부 |
| `ended_by_user` | 사용자 중단 여부 |
| `time_over` | 시간 종료 여부 |
| `time_limit_sec` | 제한시간. 현재 180초 |
| `remaining_time_sec` | 종료 시 남은 시간 |
| `exit_reason` | `completed`, `user_exit`, `time_over` |
| `status` | `completed`, `abandoned` |
| `selected_required_items` | 정답 물건 선택 수 |
| `selected_unnecessary_items` | 오답 물건 선택 수 |
| `result_detail_json` | 게임별 상세 통계 |
| `recommended_next_difficulty` | 추천 다음 난이도 |

## 7. 구현 참고

현재 구현에는 별도의 `phase` 문자열이 없고, 화면 ID와 모달 활성 상태, `state` 객체 플래그가 상태를 결정한다.

| 문서 상태 | 구현 기준 |
|---|---|
| S-00 LOADING | `runLoading()` |
| S-01 CONDITION_CHECK | `maybeShowConditionCheck()`, `screen-condition` |
| S-02 START | `screen-start` |
| S-03 TUTORIAL | `help-modal` |
| S-04 DIFFICULTY_SELECT | `screen-difficulty` |
| S-05 COUNTDOWN | `runCountdown()`, `countdown-modal` |
| S-06 ANSWER | `renderQuestion()`, `screen-play` |
| S-07 HINT | `openHintModal()`, `hint-modal` |
| S-08 FEEDBACK | `showFeedback()`, `finishQuestion()`, `revealAndAdvance()` |
| S-09 PAUSED | `pause-modal`, `state.paused` |
| S-10 EXIT_CONFIRM | `exit-modal` |
| S-11 FINISH_CHECK | `finishGame()` |
| S-12 RESULT | `screen-result` |
| S-13 SCORE | `renderScoreScreen()`, `screen-score` |
| S-14/S-15 POST_GAME_CHECK | `startPostGameConditionCheck()`, `finishPostGameConditionCheck()` |
| S-16 ERROR | `showError()`, `error-modal` |
| S-17 RETURN_TO_APP | `returnToHub()` |

앱 브리지 우선순위는 현재 `window.ReactNativeWebView.postMessage` 후 로컬 콘솔 mock이다. 전구 게임 예시의 `window.webkit.messageHandlers.gameBridge.postMessage` 경로는 `오늘의 준비물` 현재 구현에는 포함되어 있지 않다.
