WebView 로딩/오류 QA 확인 결과

검증 대상: animal-feeding-game 검증일: 2026-06-25 검증 환경: 로컬 서버 + 812x375 가로 화면
QA 번호 테스트 항목 적용 모드 확인 결과 비고
C-01 Android WebView에서 정상 로드 및 실행되는가 모든 모드 부분 통과 812x375 로컬 실행에서 로딩 완료 후 초기 체크 화면 표시, 이미지 21/21 로드, 콘솔 오류 없음. RN 브리지는 AndroidBridge.onMessage 분기 지원(js/core-config.js:7,28-29). 단, 실기기 Android WebView는 별도 단말 확인 필요.
C-02 로딩 중 빈 화면 없이 로딩 바 또는 준비 문구가 표시되는가 모든 모드 통과 새로고침 250ms 시 #loading 표시, "게임을 준비하고 있어요", 진행률 43%, blankish=false 확인. index.html:94-102, js/screen-flow.js:167-171에서 로딩 문구와 퍼센트 갱신.
C-03 네트워크 차단 상태에서 기본 화면 및 로컬 에셋이 로드되는가 모든 모드 통과 fetch, XMLHttpRequest, 외부 http(s) 리소스 없음. assetUrl은 상대경로를 그대로 사용(js/core-config.js:44-45)하고 이미지/오디오는 로컬 파일로 구성됨. 로컬 실행에서 externalLinks=[], 이미지 21/21 로드 확인.
C-04 에셋 로드 실패 시 빈 화면이 아닌 오류 안내가 표시되는가 모든 모드 통과 임시 서버에서 이미지 1개를 404로 응답시켜 재현. 오류 화면에 "게임 이미지를 불러오지 못했어요", "앱으로 돌아가 다시 시도해 주세요.", asset_load_failed, 복귀 버튼 표시. js/screen-flow.js:120-188, js/core-config.js:60-67, index.html:562-570.
C-05 GAME_ERROR 이벤트 및 error_code가 앱에 정상 반환되는가 모든 모드 실패 현재 에러 이벤트는 GAME_ERROR가 아니라 ERROR로 전송되고 payload 키도 error_code가 아니라 code임(js/core-config.js:48-55). 복귀 버튼은 RETURN_TO_APP payload에 error_code를 보내지만(js/result-bridge.js:667-674), 에셋 실패 재현 로그도 ERROR:asset_load_failed로 확인되어 명세와 불일치.
