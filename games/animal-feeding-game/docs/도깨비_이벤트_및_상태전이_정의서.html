1. 문서 개요

이 문서는 도깨비야! 무슨 색을 먹니? 게임의 주요 상태, 상태 전이, 앱-게임 연동 이벤트, 결과 저장 경계를 정의한다. Cplat 개발팀이 게임 클라이언트 구현, 효담콜 앱 연동, 케어/AI 보조 모드 진입 정책, 결과 저장 API 연계를 확인할 때 참조하는 기준 문서다.

현재 활성 게임 유형은 색/종류에 맞는 도깨비에게 먹이 주기이다. 내부 게임 키는 animal_feeding이며, 문항 단위 미션 키는 feed_animal과 leave_item이다. feed_animal은 음식의 색 또는 속성에 맞는 도깨비를 고르는 문항이고, leave_item은 팥죽/부적 같은 예외 물건을 아무 도깨비에게도 주지 않는 문항이다.

코드에는 이전 동물 먹이주기 구조의 식별자가 일부 남아 있어 animal-feeding-game, tiger, monkey, squirrel, panda, animal_count, target_animals 같은 이름을 사용한다. 실제 화면에서는 각각 빨간/초록/하얀/노란 도깨비와 선택지 수를 의미한다.

2. 상태 목록

화면 상태는 SCREENS 배열에 정의된 DOM 화면 단위이고, 세션 상태는 state._status 및 state._paused로 관리한다.

화면 상태
상태 ID 상태명 진입 조건 주요 이탈 조건
loading 로딩 페이지 로드 직후, 이미지 에셋 preload 시작 모든 에셋 로딩 성공 시 READY 전송 후 시작 흐름으로 이동, 실패 시 error
start 시작 로딩 완료 후 수동 시작 모드 진입, 컨디션 체크 완료 후 복귀, 결과 화면 확인 후 복귀 시작 버튼, 난이도 선택, 진행방법 확인, 앱 복귀 버튼
precheck 시작 전 컨디션 체크 standard 모드에서 난이도 선택 전 컨디션 체크가 필요한 경우 CONDITION_CHECK 전송 후 start 난이도 선택 단계로 이동
how 진행방법 show_how_to_play=true이고 최초 진행방법 확인이 필요한 경우 시작 버튼 클릭 시 ready, 건너뛰기 시 start
ready 준비 난이도/세션 설정 확정 후 카운트다운 전 짧은 대기 후 countdown
countdown 3초 카운트다운 ready 이후 카운트다운 종료 시 startSession() 호출 후 play
play 게임 진행 SESSION_START 전송 후 첫 문항 생성 전체 문항 완료, 사용자 중단, 시간 초과, 런타임 오류, pagehide
finish 마무리 체크 show_finish_check=true이고 완료/중단 후 체크가 필요한 경우 FINISH_CHECK 전송 후 보류 중인 최종 결과 전송
done 결과/종료 정상 완료 또는 중도 종료 처리 후 확인 버튼, 다시하기, 자동 복귀 타이머
mood 기분 체크 별도 후속 기분 체크 화면을 사용하는 레거시 경로 MOOD_CHECK 및 RETURN_TO_APP
error 오류 에셋 로딩 실패 또는 런타임 오류 복귀 버튼으로 RETURN_TO_APP
세션 내부 상태
필드 값 의미 저장 반영
state === null 세션 없음 아직 게임 세션이 시작되지 않았거나 결과 처리 후 새 세션 대기 중 저장 대상 아님
state._status running 세션 진행 중 최종 저장 전 상태
state._status completed 계획된 문항을 모두 끝낸 정상 완료 SESSION_COMPLETE payload의 status=completed
state._status abandoned 사용자 중단, 시간 초과, 앱 종료 등으로 세션 중단 SESSION_ABORT payload의 status=abandoned
state._status error 진행 중 런타임 오류로 세션 종료 SESSION_ABORT payload의 status=error
state._paused true / false 일시정지 여부. 일시정지 중에는 타이머와 입력 처리를 멈춘다. SESSION_PAUSE, SESSION_RESUME, pause_count

3. 상태 전이 정의

3-1. 초기 진입

순서 트리거 처리 이벤트 다음 상태
1 페이지 로드 URL query를 읽어 mode, difficulty, 표시 옵션을 정규화한다. - loading
2 loading() 도깨비, 음식, 정답 이미지 preload를 수행하고 로딩바를 갱신한다. LOADING_PROGRESS loading
3 에셋 로딩 성공 assetsReady=true로 표시하고 앱에 준비 완료를 알린다. READY, DISPLAY_REQUEST 모드에 따라 precheck, start, 또는 자동 시작 흐름
4 에셋 로딩 실패 asset_load_failed 오류를 보고한다. ERROR error
5 앱 CONFIG 수신 런타임 config를 적용하고 모드 UI를 갱신한다. 에셋 준비가 끝났고 auto_start 조건이 맞으면 자동 시작한다. CONFIG_APPLIED, DISPLAY_REQUEST 현재 상태 유지 또는 자동 시작 흐름

3-2. 시작 전 흐름

흐름 조건 전이 비고
standard 기본 show_difficulty_select=true, auto_start=false loading -> precheck -> start 난이도 선택 -> how 또는 ready -> countdown -> play 컨디션 체크는 CONDITION_CHECK로 기록한다. 진행방법 화면은 localStorage.af_seen_how=1이면 생략될 수 있다.
reminder 기본 auto_start=true loading -> ready -> countdown -> play 기본 난이도는 normal, 완료 후 자동 복귀 기본값은 3000ms이다.
care 수동 시작, 쉬운 구성 loading -> start -> ready -> countdown -> play 기본 difficulty=easy, animal_count=2, question_count=5, trash_count=0, 부드러운 피드백 사용.
ai_assisted 수동 시작, AI 보조 복귀 문구 loading -> start -> ready -> countdown -> play care와 유사하되 앱 복귀 문구와 실행 출처를 AI 보조 맥락으로 해석한다.

3-3. 게임 진행 흐름

순서 상태/함수 처리 이벤트
1 startSession(diff) 세션 ID, 난이도, 문항 수, 도깨비 구성, 문항 queue, 시작 시각, 타이머를 초기화한다. SESSION_START
2 nextQuestion() 현재 문항의 음식/예외 물건과 선택 가능한 도깨비를 화면에 표시한다. QUESTION_START
3 사용자 입력 터치, 드래그, 키보드, 외부 입력, 예외 물건 자동 대기 입력을 처리한다. 문항 종료 전까지 중간 이벤트 없음
4 정답 selectedTargetId, 응답 시간, 입력 타입을 기록하고 다음 문항으로 넘어간다. QUESTION_RESULT
5 오답 오답 횟수, 선택 변경, 드래그 실패를 기록한다. 2회 이상 오답 시 설정에 따라 힌트를 표시한다. 힌트 버튼 사용 시 HELP_USED, 문항 종료 시 QUESTION_RESULT
6 최대 오답 오답 3회 이상이면 정답을 표시하고 answer_revealed=true, forced_advance_reason=max_wrong_attempts로 다음 문항으로 이동한다. QUESTION_RESULT
7 예외 물건 leave_item 문항에서 2초 동안 아무 도깨비에게도 주지 않으면 input_type=idle로 자동 정답 처리한다. QUESTION_RESULT
8 마지막 문항 이후 state._idx >= plannedRounds이면 정상 완료 처리한다. SESSION_COMPLETE

3-4. 일시정지, 종료, 결과 흐름

트리거 처리 최종 상태 이벤트
사용자 종료 버튼 pauseSession("user_pause") 후 종료 확인 모달 표시. 계속하기는 resumeSession("user_resume"), 그만하기는 finishSession(false, "user_quit"). abandoned SESSION_PAUSE, SESSION_RESUME, SESSION_ABORT
앱 PAUSE/RESUME 앱 명령으로 세션 타이머, 음성, 자동 정답 대기 타이머를 멈추거나 재개한다. running SESSION_PAUSE, SESSION_RESUME
앱 QUIT finishSession(false, reason || "app_quit")로 종료한다. abandoned SESSION_ABORT
제한 시간 초과 타이머가 0 이하가 되면 timedOut=true, abandon_reason=time_limit으로 종료한다. abandoned SESSION_ABORT
런타임 오류 ERROR를 먼저 전송하고, 진행 중 세션이 있으면 finishSession(false, "runtime_error", error)를 호출한다. error ERROR, SESSION_ABORT
pagehide 진행 중 세션이면 finishSession(false, "pagehide")로 중단 처리한다. abandoned SESSION_ABORT
완료 후 마무리 체크 show_finish_check=true이면 최종 결과 이벤트를 잠시 보류하고 finish 화면에서 응답을 받은 뒤 전송한다. completed 또는 abandoned CONDITION_CHECK, FINISH_CHECK, SESSION_COMPLETE 또는 SESSION_ABORT
자동 복귀 auto_return_ms가 0보다 크면 결과 전송 후 지정 시간 뒤 앱 복귀를 요청하고 허브 URL로 이동한다. 결과 처리 완료 RETURN_TO_APP

4. 이벤트 명세

문서 기준의 공통 이벤트 래퍼는 아래 형식이다.

{
  "type": "EVENT_NAME",
  "payload": {},
  "timestamp": "2026-06-24T00:00:00.000Z"
}
현재 구현의 RN(message) 함수는 type과 payload를 그대로 직렬화하며 timestamp를 자동으로 추가하지 않는다. 저장/감사용 timestamp가 필요하면 앱 수신 시각을 보강하거나 게임의 RN 함수에서 공통 래퍼를 확장해야 한다.

React Native WebView 환경에서는 window.ReactNativeWebView.postMessage(JSON.stringify(message))를 사용한다. iOS 네이티브 핸들러가 있는 경우 window.webkit.messageHandlers.gameBridge.postMessage(message), Android 브릿지가 있는 경우 window.AndroidBridge.onMessage(JSON.stringify(message))도 지원한다. 로컬 QA에서는 qa=1 query를 붙였을 때 parent/opener 창으로 QA 메시지를 전달한다.

4-1. 게임 -> 앱

이벤트 발생 시점 주요 payload 앱 처리 기준
LOADING_PROGRESS 에셋 로딩 진행 중 progress 로딩 UI 또는 WebView 준비 상태 표시
READY 에셋 로딩 및 초기 준비 완료 version 앱에서 게임 준비 완료로 판단
CONFIG_APPLIED 앱 CONFIG 적용 후 config_snapshot 앱이 전달한 모드/난이도/표시 옵션 반영 여부 검증
DISPLAY_REQUEST 초기 준비, config 적용, 사용자 표시 요청 시 reason, fullscreen, orientation_lock, capabilities, native_hint 네이티브 앱의 전체화면/가로모드 전환 요청으로 처리
DISPLAY_APPLIED 브라우저 fullscreen/orientation lock 시도 후 reason, fullscreen, orientation, capabilities 실제 WebView 표시 적용 결과 추적
CONDITION_CHECK 시작 전 컨디션 체크 제출 또는 마무리 체크 중 post 기분 항목 제출 phase, skipped, mood, mood_label, sleep_hours 컨디션과 수행 결과 비교 분석. 시작 전 값은 최종 payload의 pre_condition_check에도 포함된다.
SESSION_START 세션 시작 직후 sessionId, contentId, gameKey, version, mode, difficulty, plannedRounds, total_questions, target_animals, trash_count 실시간 시작 로그. 최종 저장은 완료/중단 이벤트 기준.
QUESTION_START 각 문항 표시 시 question_id, question_index, question_type, item, choices, correct_answer, input_modes_enabled 실시간 문항 제시 로그 또는 외부 음성/접근성 입력 매칭 기준.
QUESTION_RESULT 각 문항 종료 시 raw 문항 결과, question_log 문항별 분석. 최종 payload의 question_logs에도 누적 포함된다.
HELP_USED 도움 버튼 클릭 시 session_id, content_id, game_key, question_id, question_index 힌트 사용 횟수 및 도움 필요도 추적.
FINISH_CHECK 마무리 체크 제출 또는 건너뛰기 시 mood, fatigue, difficulty, help_needed, replay_wanted, 각 항목별 skipped 종료 후 상태와 재시도 의사 저장. 최종 payload의 finish_check와 result_detail_json에도 반영된다.
SESSION_COMPLETE 계획된 문항을 모두 완료한 뒤 최종 결과 전체 payload, status=completed 결과 저장 API 호출 기준 이벤트
SESSION_ABORT 사용자 중단, 시간 초과, 앱 종료, pagehide, 런타임 오류 종료 시 최종 결과 전체 payload, status=abandoned 또는 status=error, abandon_reason, abandon_step 중단/오류 결과 저장 API 호출 기준 이벤트
SESSION_PAUSE, SESSION_RESUME 사용자 또는 앱 명령으로 일시정지/재개 시 session_id, reason 활성 진행 시간 계산 및 중단 분석 참고.
AUDIO_APPLIED 음성/효과음/배경음 설정 적용 후 voice, effect_sound_enabled, background_music_enabled 접근성/음향 설정 확인.
ERROR 에셋 또는 런타임 오류 발생 시 code, message, recoverable, phase 오류 분석. 진행 중 세션이 있으면 이어서 SESSION_ABORT가 전송될 수 있다.
RETURN_TO_APP 확인 버튼, 시작 화면 복귀, 오류 화면 복귀, 자동 복귀 시 session_id, status, mode, auto_return, reason 앱 화면 전환 및 허브 복귀 처리.
MOOD_CHECK 레거시 mood 화면에서 기분 선택 또는 건너뛰기 시 phase, mood, skipped 현재 기본 흐름에서는 FINISH_CHECK가 우선이다. 유지 여부는 후속 정리 필요.

4-2. 앱 -> 게임

이벤트 payload 처리 비고
CONFIG 모드, 난이도, 세션 ID, 표시/입력/오디오 옵션 applyRuntimeConfig()로 런타임 설정을 적용한다. 현재 구현의 수신 이벤트명은 APP_CONFIG가 아니라 CONFIG이다.
EXTERNAL_ANSWER selected_answer 또는 selectedAnswer, input_type, raw_transcript, confidence 현재 문항의 도깨비 ID/라벨 또는 no_target 별칭과 매칭되면 선택을 적용한다. 매칭 성공 시 문항 로그의 input_type은 기본 external로 기록된다.
PAUSE 없음 또는 임의 payload pauseSession("app_command") 진행 중 세션이 아니거나 이미 정지 상태이면 무시한다.
RESUME 없음 또는 임의 payload resumeSession("app_command") 진행 중 세션이 아니거나 정지 상태가 아니면 무시한다.
MUTE muted=true로 해석, 추가 오디오 옵션 허용 음성, 효과음, 배경음을 끈다. 적용 후 AUDIO_APPLIED를 전송한다.
UNMUTE muted=false로 해석, 추가 오디오 옵션 허용 음성, 효과음, 배경음을 켠다. 적용 후 AUDIO_APPLIED를 전송한다.
SET_AUDIO voice, voice_guide_enabled, effect_sound_enabled, background_music_enabled, backgroundMusic 오디오 세부 설정을 적용한다. 적용 후 AUDIO_APPLIED를 전송한다.
QUIT reason finishSession(false, reason || "app_quit") 최종 SESSION_ABORT를 전송한다.
ENTER_DISPLAY, ENTER_FULLSCREEN, LOCK_ORIENTATION 없음 또는 임의 payload enterGameDisplay("app_command")로 전체화면/가로모드 적용을 재시도한다. DISPLAY_REQUEST, DISPLAY_APPLIED가 전송된다.

CONFIG payload 예시

{

  "payload": {

5. 모드별 분기 요약

모드 기본 진입 기본 설정 결과/복귀
standard 시작 전 컨디션 체크, 난이도 선택, 진행방법 화면 사용 난이도 선택 표시, 점수 표시, 진행률 표시, 도움 버튼 표시, 마무리 체크 표시, 다시하기 허용 완료 또는 사용자 중단 후 done. 자동 복귀 기본값 없음.
reminder 로딩 완료 후 자동 시작 기본 difficulty=normal, 타이머/진행률 표시, 점수/도움/마무리 체크 숨김 완료 후 auto_return_ms=3000 기준으로 앱 복귀 요청.
care 시작 화면에서 수동 시작 기본 difficulty=easy, question_count=5, animal_count=2, trash_count=0, 부드러운 피드백 완료 후 자동 복귀. 보호자/케어 세션 맥락은 앱 저장 계층에서 play_source=care_session 등으로 보강.
ai_assisted 시작 화면에서 수동 시작 care와 동일한 쉬운 구성, AI 보조 복귀 문구 완료 후 자동 복귀. 앱 저장 계층에서 play_source=ai_recommendation 등으로 보강.

6. 구현 결정사항

  • WebView 게임은 API 서버를 직접 호출하지 않고 앱에 결과 payload만 전달한다.
  • 최종 저장 기준 이벤트는 SESSION_COMPLETE와 SESSION_ABORT이다. 런타임 오류 종료도 이벤트명은 SESSION_ABORT이고 payload의 status가 error이다.
  • 현재 앱에서 게임으로 보내는 설정 이벤트명은 CONFIG이다. 기존 앱 표준이 APP_CONFIG라면 앱 브릿지에서 변환하거나 게임에 alias를 추가한다.
  • 문항 유형은 feed_animal과 leave_item이다. leave_item은 예외 물건을 아무 도깨비에게도 주지 않는 선택지이며 correct_answer=no_target으로 기록한다.
  • 오답 3회 이상이면 정답을 보여주고 다음 문항으로 넘어간다. 이 경우 is_correct=false, answer_revealed=true, forced_advance_reason=max_wrong_attempts로 분석한다.
  • 일시정지 중 시간은 duration_ms 계산에서 제외된다. pause_count는 결과 payload에 포함한다.
  • 전체화면/가로모드는 게임이 브라우저 API를 시도하지만, WebView 환경에서는 앱이 DISPLAY_REQUEST를 받아 네이티브 표시 정책을 적용하는 것을 기준으로 한다.
  • 현재 timestamp, EXTERNAL_ANSWER_IGNORED, game_version root 필드 자동 생성은 구현되어 있지 않다. 저장 API 요청 시 앱이 보강하거나 게임 공통 브릿지에서 확장한다.

8. 저장 API 전달 경계

WebView 게임은 API 서버를 직접 호출하지 않는다. 게임은 window.ReactNativeWebView.postMessage 등 브릿지로 결과 payload를 호스트 앱에 전달하고, 앱이 결과 저장 API를 호출한다.

결과 저장 API로 넘어갈 때 MVP 필수 필드는 senior_id, content_id, game_key, game_version, session_id, play_source, status, started_at, ended_at, duration_ms, game_result다. guardian_id, assignment_id, alarm_id, schedule_id, client_context, voice_context는 앱 실행 맥락에 따라 nullable 또는 조건부로 전달한다.

{
  "senior_id": "senior_001",
  "guardian_id": null,
  "assignment_id": "assignment_001",
  "alarm_id": null,
  "schedule_id": null,
  "content_id": "cognitive_animal_feeding_001",
  "game_key": "animal_feeding",
  "game_version": "2.0.0",
  "session_id": "session_001",
  "play_source": "care_session",
  "status": "completed",
  "started_at": "2026-06-24T00:00:00.000Z",
  "ended_at": "2026-06-24T00:03:00.000Z",
  "duration_ms": 180000,
  "client_context": {
    "device_id": "device_001",
    "platform": "android",
    "app_version": "1.0.0",
    "timezone": "Asia/Seoul"
  },
  "voice_context": {
    "voice_profile_id": "voice_default_001",
    "voice_owner_type": "system",
    "voice_owner_id": null
  },
  "game_result": {
    "...": "SESSION_COMPLETE 또는 SESSION_ABORT payload 원본"
  }
}
  • 중복 저장 방지는 session_id 또는 assignment_id + session_id 기준을 권장한다.
  • 원본 WebView 결과는 game_result_json으로 그대로 보존한다.
  • 보고/통계용 공통 컬럼은 total_questions, correct_count, wrong_count, hint_count, avg_response_time_ms 등을 payload에서 추출한다.
  • question_logs는 별도 game_question_logs 테이블로 분리 저장하거나, MVP 단계에서는 game_result_json과 result_detail_json에 보존한다.
  • 히스토리 재실행은 기존 결과를 덮어쓰지 않고 새 session_id와 play_source=history_replay로 저장한다.
  • 오류 종료는 status=error, error_code, error_message, abandon_reason=runtime_error를 함께 저장한다.

9. 상태별 QA 확인 항목

영역 확인 항목 기대 결과
초기 로딩 에셋 로딩 중 LOADING_PROGRESS, 완료 시 READY가 전송되는지 확인 로딩 실패가 없으면 시작 흐름으로 진입한다.
CONFIG 적용 앱에서 CONFIG를 보낸 뒤 CONFIG_APPLIED.config_snapshot 확인 모드, 난이도, 문항 수, 표시 옵션이 의도대로 반영된다.
표시 모드 DISPLAY_REQUEST 수신 후 앱이 전체화면/가로모드를 적용하는지 확인 WebView가 1280x720 기준 화면을 가로모드로 안정적으로 표시한다.
시작 전 체크 standard에서 컨디션 체크 제출/건너뛰기 CONDITION_CHECK와 최종 payload의 pre_condition_check가 일치한다.
세션 시작 SESSION_START payload의 문항 수, 도깨비 수, 예외 물건 수 확인 모드별 config 매트릭스와 일치한다.
문항 진행 정답, 오답, 3회 오답, 힌트, 드래그 실패, 키보드 입력 확인 QUESTION_RESULT.question_log의 시도/힌트/응답 시간이 정확하다.
예외 물건 leave_item 문항에서 아무 곳에도 주지 않고 2초 대기 correct_answer=no_target, input_type=idle로 정답 처리된다.
외부 입력 EXTERNAL_ANSWER.selected_answer로 도깨비 ID/라벨 또는 no_target 전달 매칭 성공 시 선택이 적용되고 input_type=external로 기록된다.
일시정지 앱 PAUSE/RESUME, 사용자 종료 모달 계속하기 확인 SESSION_PAUSE, SESSION_RESUME과 pause_count가 반영된다.
정상 완료 모든 문항 완료 SESSION_COMPLETE, status=completed, completion_rate=1
중도 종료 사용자 그만하기, 앱 QUIT, 시간 초과, pagehide 확인 SESSION_ABORT, status=abandoned, 적절한 abandon_reason
오류 종료 런타임 오류 또는 에셋 로딩 실패 시나리오 확인 ERROR가 전송되고, 진행 중 세션은 SESSION_ABORT.status=error로 저장 가능하다.
저장 경계 앱이 SESSION_COMPLETE/SESSION_ABORT 수신 후 API 요청 생성 필수 저장 필드와 원본 game_result_json이 누락되지 않는다.

10. 오픈 이슈 및 후속 정리

항목 현재 상태 후속 방향

APP_CONFIG 호환성 현재 게임은 CONFIG만 수신 앱 브릿지 변환 또는 게임 수신 alias 추가 여부 결정
