도깨비야! 무슨 색을 먹니? - 모드별 config 매트릭스

앱 진입 모드별 기본 config, 난이도별 실행값, 결과 payload 반영 기준을 정리한 WebView 연동 문서입니다.

작성 기준: js/core-config.js, js/session-board.js, js/play-input.js, js/result-bridge.js, data/animal-feeding-content.json

게임 식별자: content_id=cognitive_animal_feeding_001, game_key=animal_feeding, game_version=2.0.0

작성일: 2026-06-24

1. 적용 범위

이 문서의 mode는 게임 내부 미션이 아니라 앱에서 게임으로 진입한 방식을 뜻합니다. 결과 저장 API나 분석 레이어에서는 mode를 app_mode로 정규화하고, 실제 문항 미션은 question_logs[].question_type 또는 game_mode/mission_mode로 구분하는 것을 권장합니다.

내부 폴더명과 코드 식별자는 이전 구조 때문에 animal-feeding-game, animal_feeding, animal_count, target_animals를 사용합니다. 화면 의미는 도깨비 게임이며, tiger, monkey, squirrel, panda는 각각 빨간/초록/하얀/노란 도깨비를 가리킵니다.

6. 앱에서 config를 전달하는 방법

config 수신 경로와 우선순위
순서 경로 예시 비고
1 기본값 normalizeRuntimeConfig({}) 페이지 로드 시 기본 런타임 config가 만들어집니다.
2 URL query ?mode=reminder&difficulty=hard&question_count=10 초기 로드 시 적용됩니다.
3 JS bridge helper window.AnimalFeedingGame.configure(payload) { type:"CONFIG", payload }와 동일하게 처리됩니다.
4 앱 postMessage { "type": "CONFIG", "payload": { "...": "..." } } React Native WebView, iOS messageHandlers, AndroidBridge, DOM message를 통해 수신합니다.

현재 구현은 window.GAME_CONFIG 전역 객체를 자동으로 읽지 않습니다. 앱에서 런타임 중 설정을 바꾸려면 CONFIG 메시지나 window.AnimalFeedingGame.configure(payload)를 사용합니다.

7. 결과 payload 공통 반환 기준

WebView 게임은 결과 저장 API를 직접 호출하지 않습니다. 완료, 중단, 오류 발생 시 window.ReactNativeWebView.postMessage 등 bridge를 통해 앱에 결과 payload를 전달하고, 앱이 서버 저장 API를 호출합니다.

결과 저장 매핑 기준
WebView payload API/DB 권장 필드 설명
payload.mode app_mode 앱 진입 모드입니다. 서버의 play_source와 별도로 보존할 수 있습니다.
question_logs[].question_type game_mode 또는 mission_mode feed_animal, leave_item로 문항 미션을 구분합니다.
payload.version game_version 현재 버전은 2.0.0입니다.
payload.config_snapshot config_snapshot 실제 적용된 런타임 값입니다. 앱 전달값보다 이 값을 우선 분석 기준으로 삼습니다.
payload.result_detail_json result_detail_json 게임별 상세 결과입니다. 원본 payload도 game_result_json으로 별도 보존합니다.
payload.question_logs[] game_question_logs.raw_log_json 문항별 로그 테이블을 둘 경우 각 문항 로그의 원본을 보존합니다.

attempt_count 도깨비 또는 정리 선택 시도 횟수입니다. 정리 문항 자동 정답은 0일 수 있음
wrong_tap_count 오답 위치에 놓거나 선택한 횟수입니다. 3회 도달 시 정답 공개 후 다음 문항
answer_revealed 최대 오답 후 정답을 공개했는지 여부입니다. true면 정답 공개 문항으로 별도 분석 가능
external_input 앱이 전달한 외부 답변의 원본, confidence 등을 담습니다. 음성/STT 연동 시 사용

11. 저장/API 연동 메모

  • 앱은 최종 SESSION_COMPLETE, SESSION_ABORT payload를 받은 뒤 서버 저장 API를 호출합니다.
  • 서버 저장 시 senior_id, guardian_id, assignment_id, alarm_id, schedule_id, play_source는 앱 실행 맥락에서 보강합니다.
  • 중복 저장 방지는 session_id 또는 assignment_id + session_id 기준을 권장합니다.
  • 원본 WebView 결과는 game_result_json으로 그대로 보존하고, result_detail_json과 공통 reporting column을 별도로 추출합니다.
  • 히스토리 재실행은 기존 결과를 덮어쓰지 않고 새 session_id와 play_source=history_replay로 저장합니다.
  • 현재 게임은 recommended_next_difficulty를 계산하지 않습니다. 필요하면 서버/앱 분석 레이어에서 correct_count, wrong_count, avg_response_time_ms, hint_count 기준으로 후처리합니다.
