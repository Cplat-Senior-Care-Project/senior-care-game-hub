도깨비야! 무슨 색을 먹니? - 데이터 수집 항목표

WebView 기반 인지활동 콘텐츠의 결과 저장 및 앱 연동을 위한 수집 데이터 정의서

작성 기준: 현재 구현 파일 js/core-config.js, js/session-board.js, js/play-input.js, js/result-bridge.js

적용 게임: animal_feeding / cognitive_animal_feeding_001 / 버전 2.0.0

작성일: 2026-06-24

1. 문서 목적

본 문서는 WebView 기반 인지활동 콘텐츠인 도깨비야! 무슨 색을 먹니? 게임에서 수집 및 전달하는 데이터 항목을 현재 게임 구현 기준으로 정리한다.

도깨비 게임은 화면에 제시된 먹이 또는 정리 물건을 보고, 색이 맞는 도깨비에게 보내거나 아무 도깨비에게도 주지 않는 판단을 수행하는 색상-의미 연결형 인지활동 게임이다. 내부 코드에는 이전 구조의 명칭이 남아 있어 animal_feeding, animal_count, target_animals, tiger, monkey, squirrel, panda 같은 필드명이 사용된다. 실제 화면 의미는 각각 도깨비 게임과 색상별 도깨비를 가리킨다.

게임은 API 서버를 직접 호출하지 않고, 주요 상태 이벤트와 최종 결과를 window.ReactNativeWebView.postMessage로 호스트 앱에 전달한다. 호스트 앱은 전달받은 payload에 senior_id, play_source 등 실행 맥락 필드를 보강한 뒤 결과 저장 API에 전달한다.

2. 수집 범위 및 원칙

수집 범위 및 원칙
구분 내용
수집 목적 게임 참여 여부, 문항별 정오답, 색상-먹이 연결 판단 흐름, 힌트 필요도, 반응 시간, 중도 종료 및 오류 원인, 다음 난이도 또는 케어 리포트 참고 지표를 확보한다.
수집 단위 1회 실행 세션, 문항별 결과, 선택 과정 집계값, 게임별 상세값, WebView 상태 이벤트를 수집한다.
전송 방식 게임 내부 RN(message) 함수가 JSON 메시지를 만들고 ReactNativeWebView.postMessage, iOS webkit.messageHandlers.gameBridge, Android AndroidBridge.onMessage 순서로 전달한다.
저장 기준 최종 저장은 SESSION_COMPLETE, SESSION_ABORT, 오류 종료 시 payload를 기준으로 한다. 중간 이벤트는 실시간 상태 추적 또는 디버깅 보조용으로 사용한다.
원본 보존 DB 저장 시 정규화 컬럼과 별개로 게임이 반환한 전체 결과 payload를 game_result_json 또는 동등한 JSON 컬럼에 보존해야 한다.
개인 식별자 senior_id, guardian_id, assignment_id, alarm_id, schedule_id는 게임 내부에서 직접 생성하지 않으며 호스트 앱 또는 API 서버에서 결합한다.

4. 세션 결과 root 필드

아래 표는 SESSION_COMPLETE 또는 SESSION_ABORT 메시지의 payload root에 포함되는 주요 필드와, API 저장 시 호스트 앱이 보강해야 하는 필드를 함께 정리한 것이다.

현재 WebView payload는 호환성을 위해 sessionId와 session_id, contentId와 content_id처럼 camelCase와 snake_case가 함께 존재할 수 있다. API 저장 시에는 snake_case를 표준으로 정규화하는 것을 권장한다.
세션 결과 root 필드
필드명 타입 생성 주체 설명 비고
session_id / sessionId String 게임 또는 호스트 1회 실행 세션을 구분하는 ID이다. 호스트가 전달하지 않으면 게임이 내부 uid()로 생성한다. 중복 저장 방지 기준
content_id / contentId String 게임 또는 호스트 콘텐츠 ID이다. 기본값은 cognitive_animal_feeding_001이다. API 필수
game_key / gameKey String 게임 또는 호스트 게임 유형 ID이다. 기본값은 animal_feeding이다. API 필수
version String 게임 현재 게임 버전이다. 구현 기준값은 2.0.0이다. API 저장 시 game_version으로 매핑 권장
gameId String 게임 레거시 호환 게임 ID이다. 현재 animal_feeding과 동일하다. 원본 JSON 보존
mode String 게임 또는 호스트 실행 모드이다. 허용값은 standard, reminder, care, ai_assisted이다. app_mode 또는 play_source 판단에 활용
difficulty String 게임 또는 호스트 적용 난이도이다. 허용값은 easy, normal, hard이다. care, ai_assisted 모드는 현재 easy로 고정된다. 난이도별 비교 분석
status String 게임 종료 상태이다. completed, abandoned, error 중 하나이다. API 필수
started_at / startedAt String 게임 세션 시작 시각이다. ISO 8601 문자열로 기록된다. API 필수
ended_at / endedAt String 또는 Null 게임 세션 종료 시각이다. 종료 payload에서는 ISO 8601 문자열로 기록된다. API 필수
duration_ms / durationMs Integer 게임 일시정지 시간을 제외한 실제 진행 시간이다. API 필수
time_limit_ms / timeLimitMs Integer 게임 세션 제한 시간이다. 기본값은 180,000ms이다. 0이면 제한 없음으로 해석 가능
timed_out / timedOut Boolean 게임 시간 제한으로 종료되었는지 여부이다. abandon_reason=time_limit와 함께 사용
total_questions / plannedRounds Integer 게임 계획된 전체 문항 수이다. 기본 10문항, 단순 모드 기본 5문항
completed_questions / completedRounds Integer 게임 실제로 완료 처리된 문항 수이다. 중도 종료 시 전체보다 작을 수 있음
correct_count / correctCount Integer 게임 정답 문항 수이다. 정답 공개로 넘어간 문항은 정답으로 집계하지 않는다. 공통 리포트 컬럼 후보
wrong_count Integer 게임 완료 문항 중 오답 문항 수이다. completed_questions - correct_count
hint_count Integer 게임 힌트를 사용한 문항 수이다. 수동 힌트와 자동 힌트 포함
retry_count Integer 게임 첫 시도 이후 추가 시도 횟수의 합계이다. sum(max(0, attempt_count - 1))
pause_count Integer 게임 세션 일시정지 횟수이다. 앱 백그라운드, 사용자 중단 모달 포함
help_open_count Integer 게임 도움말 또는 힌트 버튼을 연 횟수이다. standard 중심
interaction_count Integer 게임 정답 위치 선택을 시도한 상호작용 횟수이다. 드래그 실패는 별도 집계
avg_response_time_ms Integer 게임 문항별 응답 시간 평균이다. process.avgResponseMs 기준
completion_rate Number 게임 전체 문항 대비 완료 문항 비율이다. 0에서 1 사이
animal_count Integer 게임 세션에 등장한 도깨비 수이다. 내부 필드명은 animal이나 실제 의미는 도깨비 수이다. 난이도, 모드별 화면 복잡도
target_animals Array<String> 게임 세션에 등장한 도깨비 내부 ID 목록이다. tiger, monkey, squirrel, panda
trash_count Integer 게임 아무 도깨비에게도 주지 않아야 하는 정리 문항 수이다. 현재 hard 기본 2개
choice_count Integer 게임 선택 가능한 도깨비 수이다. 현재 animal_count와 동일
config_snapshot Object 게임 실행 당시 적용된 모드, 난이도, 표시 옵션, 음향 옵션, 제한 시간 등 설정 스냅샷이다. 원인 분석에 중요
abandoned_at, abandon_reason, abandon_step String/Object/Null 게임 중도 종료 시각, 사유, 종료 위치이다. user_quit, time_limit, pagehide, app_quit 등
error_code, error_message String 또는 Null 게임 오류 종료 시 오류 코드와 메시지이다. 오류가 없으면 null
results Array 게임 문항별 raw 결과 배열이다. question_logs보다 코드 내부 형태에 가까움
process Object 게임 평균 반응 시간, 오답 드롭, 드래그 실패 등 수행 과정 집계이다. result_detail_json.process에도 보존
reward Object 게임 참여, 보상 가능 여부, 성장값 등 레거시 보상 호환 필드이다. 현재 저장 원본 보존 권장
senior_id, guardian_id String 또는 Null 호스트/API 실행 사용자와 보호자 식별자이다. 게임 내부 직접 생성 없음
play_source String 호스트/API 실행 출처이다. reminder, manual, history_replay, ai_recommendation, care_session 등을 사용한다. 게임의 mode와 별도 관리 권장
assignment_id, alarm_id, schedule_id String 또는 Null 호스트/API 과제, 알림, 일정 실행 맥락 ID이다. nullable 또는 조건부
client_context, voice_context Object 또는 Null 호스트/API 기기, 앱, 타임존, 실제 사용 음성 프로필 등 실행 맥락이다. 게임 내부 직접 수집 없음

5. 문항별 결과 데이터: question_logs[]

question_logs[]는 각 문항이 완료될 때 생성되는 표준화된 문항 로그 배열이다. 최종 결과 payload의 root와 result_detail_json.question_logs에 함께 포함된다.

question_logs[] 필드
필드명 타입 설명 예시
session_id String 문항이 속한 세션 ID m8a7x2...
content_id String 콘텐츠 ID cognitive_animal_feeding_001
game_key String 게임 유형 ID animal_feeding
question_id String 문항별 고유 ID q9k3...
question_index Integer 1부터 시작하는 문항 순번 7

question_type String 문항 유형. 먹이 주기 문항은 feed_animal, 아무에게도 주지 않는 문항은 leave_item이다. feed_animal
cognitive_domain String 주요 인지 영역이다. 먹이 문항은 semantic_memory, 정리 문항은 selective_attention으로 기록된다. semantic_memory

6. 선택 과정 데이터

현재 게임은 사용자가 선택할 때마다 별도 저장용 ITEM_SELECTED payload를 만들지 않는다. 또한 최종 question_logs[] 안에 선택 타임라인 형태의 attempts[] 배열을 보존하지 않는다. 대신 각 문항 완료 시점에 선택 과정 집계값을 남긴다.

선택 과정 집계 필드
필드 위치 설명 활용
attempt_count question_logs[] 해당 문항에서 정답 위치 선택을 시도한 횟수이다. 재시도 필요도 분석
wrong_tap_count question_logs[], raw_results[] 오답 도깨비 또는 잘못된 위치로 보낸 횟수이다. 오답 빈도, 색상 연결 혼동 분석
drag_fail_count question_logs[], raw_results[] 드래그했지만 유효한 선택 영역에 닿지 않은 횟수이다. 조작 난이도, 미세운동 부담 참고
changed_answer_count question_logs[], raw_results[] 선택한 답을 다른 답으로 바꾼 횟수이다. 망설임 또는 자기수정 흐름 참고
first_response_time_ms question_logs[] 첫 터치 또는 드래그 시작까지 걸린 시간이다. 주의 전환 및 초기 반응 속도 참고
response_time_ms question_logs[] 문항 전체 처리 시간이다. 문항 난이도와 수행 부담 분석
answer_revealed, forced_advance_reason question_logs[] 최대 오답 3회 도달 후 정답을 보여주고 다음 문항으로 넘긴 경우를 표시한다. 오답 누적에 따른 지원 필요도 판단
external_input question_logs[] 앱에서 EXTERNAL_ANSWER로 답을 전달한 경우 입력 출처와 원문을 보존한다. AI 또는 접근성 입력 연동 분석

7. 게임별 상세값: result_detail_json

result_detail_json은 공통 root 필드를 훼손하지 않고 도깨비 게임의 세부 실행 맥락과 원본 문항 데이터를 보존하기 위한 JSON 객체이다.

result_detail_json 주요 필드
필드명 타입 설명
session Object 세션 요약값이다. session_id, status, duration_ms, correct_count, wrong_count, completion_rate 등을 포함한다.
config_snapshot Object 실행 당시 설정 스냅샷이다. 모드, 난이도, 문항 수, 도깨비 수, 제한 시간, 음향, 힌트, 자동 복귀 등의 설정을 포함한다.
question_logs Array 최종 표준 문항 로그 배열이다. root의 question_logs와 동일한 기준으로 보존된다.
raw_results Array 게임 내부 문항 결과 원본 배열이다. question_logs보다 내부 구현 필드명에 가깝고 questionId, itemId, correctTargetId, selectedTargetId, attempts 등을 포함한다.
process Object 수행 과정 집계값이다. avgFirstReactionMs, avgResponseMs, totalWrongDrop, totalDragFail, totalTargetChange, hintUsedCount를 포함한다.
reward Object 또는 Null 레거시 보상 호환 정보이다. participated, missionApplied, rewardEligible, growthDelta, streakApplied, careAction 등을 포함한다.
pre_condition_check Object 또는 Null 시작 전 컨디션 체크 결과이다. 현재 기본 구조는 mood, sleepHours, skipped, completed이다.
condition_check, fatigue_check, difficulty_check, help_check, replay_check Object 또는 Null 마무리 체크 제출 후 추가되는 종료 후 상태 및 피드백 데이터이다. standard 모드에서 주로 사용된다.
finish_check, finish_check_payload Object 또는 Null 종료 후 기분, 피로도, 난이도 체감, 도움 필요 여부, 다시 하기 의사를 묶은 원본 payload이다.
abandon Object 중도 종료 또는 오류 종료 관련 정보이다. abandoned_at, abandon_reason, abandon_step, error_code, error_message를 포함한다.
animal_count, choice_count, target_animals Integer / Array 세션에서 사용된 도깨비 수와 내부 ID 목록이다.
item_count, trash_count Integer 완료된 문항 수와 정리 문항 수이다.
used_drag Boolean 이번 세션에서 드래그 입력이 실제로 사용되었는지 여부이다.
input_modes_enabled Array<String> 허용된 입력 방식이다. 드래그 사용 시 touch, drag, external이 포함된다.
soft_feedback, auto_hint_enabled Boolean 부드러운 피드백과 자동 힌트 사용 여부이다.
difficulty_downshifted Boolean 난이도 자동 하향 여부이다. 현재 구현에서는 false로 기록된다.

9. 오류 데이터

게임 중 오류가 발생하면 ERROR 이벤트가 먼저 전송되고, 실행 중 세션이 있다면 finishSession(false, "runtime_error", error) 경로를 통해 상태가 error인 최종 결과 payload가 전송된다.

오류 데이터 항목
필드 위치 설명
code / error_code ERROR.payload, 최종 결과 root 오류 코드이다. 대표값은 runtime, asset_load_failed, unknown 등이다.
message / error_message ERROR.payload, 최종 결과 root 오류 메시지이다. 사용자 노출 문구와 별도로 디버깅용 원문을 보존한다.
recoverable ERROR.payload 앱 복귀 또는 재시도 가능 여부이다.
phase ERROR.payload 오류 발생 화면 또는 처리 단계이다.
status 최종 결과 root 오류 종료 시 error로 기록된다.
abandon_reason 최종 결과 root 오류 종료 경로에서는 runtime_error가 기록될 수 있다.

11. 수집 제외 또는 현재 미수집 항목

수집 제외 및 현재 미수집 항목
항목 상태 사유 또는 처리 방향
senior_id, guardian_id 게임 미생성 개인 및 보호자 식별자는 호스트 앱 또는 API 서버에서 결합한다.
play_source 게임 미생성 게임의 mode만으로 실행 출처를 확정하지 말고, 호스트 앱이 reminder, manual, history_replay 등을 명시한다.
assignment_id, alarm_id, schedule_id 게임 미생성 알림, 과제, 일정 맥락은 앱 또는 서버의 실행 컨텍스트에서 관리한다.
선택별 ITEM_SELECTED 이벤트 미수집 현재 구현은 선택 순간마다 별도 저장 이벤트를 보내지 않고 문항 종료 시 집계값만 보존한다.
question_logs[].attempts[] 타임라인 미수집 개별 시도 배열은 없으며 attempt_count, wrong_tap_count, changed_answer_count 등으로 요약한다.
좌표, 드래그 경로, 세밀한 포인터 이동 미수집 개인별 조작 궤적은 저장하지 않는다. 현재는 드래그 실패 횟수만 보존한다.
음성 원본, 마이크 데이터, STT 처리 결과 미수집 게임은 마이크 권한 요청이나 음성 인식을 직접 수행하지 않는다. 외부 답변이 들어오면 전달받은 transcript만 선택적으로 보존한다.
진단, 치료, 의학적 판정 데이터 수집 제외 본 게임의 결과는 인지활동 참여 및 수행 참고 지표이며 의료 진단 목적으로 사용하지 않는다.
AI 판단 결과 게임 미생성 ai_assisted 모드는 외부 입력 수신 가능 구조일 뿐, 게임 내부에서 AI 판단을 직접 생성하지 않는다.

13. API/DB 저장 메모

  • API 저장 MVP 필수 필드는 senior_id, content_id, game_key, game_version, session_id, play_source, status, started_at, ended_at, duration_ms, game_result이다.
  • 현재 게임은 version을 반환하므로 API 저장 시 game_version=payload.version으로 매핑한다.
  • guardian_id, assignment_id, alarm_id, schedule_id, client_context, voice_context는 실행 맥락에 따라 nullable 또는 조건부다.
  • DB는 정규화 컬럼과 별개로 WebView가 반환한 원본 결과를 game_result_json에 보존해야 한다. 현재 payload는 camelCase와 snake_case가 함께 있으므로 원본 보존이 특히 중요하다.
  • game_question_logs 테이블을 둘 경우 question_logs[]를 기준으로 session_id, question_id, question_index, question_type, difficulty, is_correct, selected_answer, correct_answer, attempt_count, hint_count, response_time_ms, input_type, raw_log_json을 매핑한다.
  • 중복 저장은 session_id 또는 senior_id + session_id, 내부 정책에 따라 assignment_id + session_id 기준으로 방지한다.
  • history_replay는 기존 결과를 덮어쓰지 않고 새 session_id의 별도 결과로 저장한다.
  • 중도 종료와 오류도 저장 대상이다. status=abandoned는 abandon_reason과 abandon_step을 함께 저장하고, status=error는 error_code, error_message, result_detail_json.abandon을 함께 보존한다.
  • 정리 문항의 정답은 correct_answer=no_target으로 저장된다. 리포트 표시 시에는 “아무 도깨비에게도 주지 않음”으로 변환하는 것이 좋다.
