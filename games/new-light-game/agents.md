# Agents Guide

## 0. 상위 지침

이 프로젝트의 모든 개발 작업은 아래 순서로 진행한다.

1. `PLN-LGT-001_게임 개요 보고서_v1.5` 문서를 ClickUp에서 먼저 확인한다.
2. 요구사항 명세서 `시니어_WebView_게임_요구사항정의서_리스트형.xlsx` 파일을 확인한다.
3. 위 문서들의 내용을 파악한 뒤에 로컬 프로젝트 파일을 확인하고 수정한다.

작업 중 문서와 로컬 구현이 충돌하면 문서 요구사항을 우선 검토하고, 실제 변경 전 충돌 내용을 명확히 기록한다.

> 현재 확인 사항: ClickUp 문서 `PLN-LGT-001_게임 개요 보고서_v1.5`는 확인했다. 이 프로젝트 폴더 안에서는 `시니어_WebView_게임_요구사항정의서_리스트형.xlsx` 파일이 발견되지 않았으므로, 해당 파일이 필요한 작업에서는 파일 위치를 먼저 확인해야 한다.

## 2. 핵심 게임 규칙

- 사용자는 잠깐 켜진 전구 위치를 기억한 뒤, 전구가 꺼지면 같은 위치를 터치하거나 클릭한다.
- 표준모드와 알림모드의 관찰 시간은 5초다.
- 케어모드와 AI 연동모드의 관찰 시간은 8초다.
- 관찰 중에는 선택할 수 없다.
- 정답 위치를 모두 선택하면 정답으로 처리하고 다음 문제로 자동 이동한다.
- 켜지지 않았던 위치를 누르면 오답으로 처리한다.
- 오답 3회 누적 시 정답 공개 없이 다음 문제로 자동 이동한다.
- 한 문제에서 60초 동안 답을 고르지 못하면 다음 문제로 자동 이동한다.
- 표준모드와 알림모드의 힌트는 횟수 제한 없이 사용할 수 있으며, 못 찾은 위치를 5초간 애니메이션으로 표시한다.
- 케어모드와 AI 연동모드에서는 40초가 지나면 힌트 안내문구를 띄우고 자동으로 5초간 애니메이션을 표시한다.

## 3. 난이도 기준

| 난이도 | 그리드 | 켜지는 전구 | 제한 시간 | 특징 |
| --- | --- | --- | --- | --- |
| 쉬움 | 2 x 2 | 2개 | 10분 | 초기 적응과 성공 경험 확보 |
| 보통 | 3 x 3 | 3개 | 8분 | 집중 유지와 시선 범위 확대 |
| 어려움 | 4 x 4 | 4개 | 6분 | 6번째 문제부터 무궁화 혼합 자극 추가 |

## 4. 화면 흐름

기본 화면 흐름은 다음을 따른다.

`로딩 -> 컨디션 체크 -> 시작 화면 -> 난이도 선택 -> 게임 플레이 -> 마무리 체크 -> 결과 화면 -> 시작 화면`

- 컨디션 체크는 시작 화면 진입 전 매번 수행하되 건너뛰기를 허용한다.
- 표준모드에서는 컨디션 체크와 마무리 체크를 기본 노출한다.
- 알림모드에서는 `show_condition_check`, `show_finish_check` config 값으로 노출을 제어한다.
- 케어모드와 AI 연동모드에서는 컨디션 체크를 게임 내부에서 숨기고 앱 또는 AI 흐름이 별도로 수집한다.
- 결과 화면의 종료 버튼 문구는 모든 모드에서 `효담콜로 돌아가기`를 사용한다.
- 알림, 케어, AI 연동모드에서는 다시하기 버튼을 기본 비노출한다.

## 5. 실행 모드

| 모드 | 값 | 핵심 동작 |
| --- | --- | --- |
| 표준 모드 | `standard` | 난이도 선택 가능, 타이머, 점수, 진행 상태 표시, 컨디션 체크 유지 |
| 알림 모드 | `reminder` | 앱이 지정한 난이도로 바로 시작 가능, 다시하기 기본 비노출, 완료 후 자동 복귀 |
| 케어 모드 | `care` | 타이머, 점수, 난이도 선택, 설정 버튼, 진행방법 버튼, 컨디션 체크 숨김 |
| AI 연동 모드 | `ai_assisted` | AI 대화 중 게임 호출 및 이벤트 연동, 컨디션 체크는 AI 대화에서 별도 수집 |

게임 자체가 실행 모드를 임의로 판단하거나 변경하지 않는다. 모드는 앱이 게임 실행 시 전달하는 config의 `mode` 값을 따른다.

## 6. 접근성 및 시니어 UX 원칙

- 드래그, 스와이프, 멀티터치 없이 터치와 클릭 단일 조작을 사용한다.
- 주요 버튼 높이는 64px 이상, 카드와 숫자 버튼 터치 영역은 72px 이상으로 유지한다.
- Title은 36px 이상, Body는 30px 이상, Caption은 24px 이상을 기준으로 한다.
- 배경과 텍스트 사이의 충분한 대비를 확보한다.
- 1280 x 720 기준 가로 고정 스테이지를 기기 크기에 맞게 scale 처리한다.
- `safe-area-inset`을 적용해 노치와 하단 제스처 영역에서 UI가 잘리지 않게 한다.
- 외부 CDN 의존성을 최소화하고 시스템 폰트 또는 프로젝트에서 허용한 폰트를 사용한다.
- 오답 피드백은 실패감을 줄이는 부드러운 문구를 사용한다.
- `치매 예방`, `인지력 향상`, `뇌 기능 강화`처럼 사용자에게 부담을 줄 수 있는 표현은 사용하지 않는다.

## 7. 데이터 수집 기준

게임 결과와 과정 데이터는 보호자 리포트, 참여 이력 확인, 보상 시스템 연동을 고려해 설계한다.

주요 데이터 범주는 다음과 같다.

- 세션 데이터: `sessionId`, `userId`, `gameId`, `gameVersion`, `startedAt`, `endedAt`, `totalPlayTimeMs`, `selectedDifficulty`, `completed`, `exitedEarly`, `exitReason`
- 문항별 결과 데이터: `is_correct`, `target_positions`, `selected_positions`, `attempt_count`, `correctClickCount`, `wrongClickCount`, `wrong_tap_count`, `first_response_time_ms`, `response_time_ms`
- 과정 데이터: `hint_used`, `hint_count`, `failReason`, `timeoutRoundCount`
- 문제 복잡도 데이터: `difficulty`, `grid_rows`, `grid_cols`, `grid_size`, `target_count`, `max_target_count`, `exposure_time_ms`, `question_type`, `cognitive_domain`
- 컨디션 데이터: `moodBefore`, `sleepHours`, `moodAfter`, `fatigue`, `perceivedDifficulty`, `neededHelp`, `replayIntent`

## 8. 로컬 프로젝트 구조

현재 프로젝트는 HTML, CSS, JavaScript 기반 정적 웹 게임 구조다.

- `index.html`: 화면 마크업
- `css/base.css`: 기본 변수, 전역 요소, 접근성 보조 클래스
- `css/screens.css`: 로딩/시작/상태체크/설정/결과 등 화면 단위 스타일
- `css/game-layout.css`: 플레이 HUD, 그리드, 카드, 전구/꽃/테마 오브젝트 스타일
- `css/responsive.css`: 화면 회전 안내, 모션 축소 등 반응형/디바이스 대응
- `css/feedback.css`: 애니메이션과 피드백 효과
- `css/light-theme.css`: 테마와 고대비 보정
- `css/modes/standard.css`: 표준모드 전용 표시 보정
- `css/modes/reminder.css`: 알림모드 전용 표시 보정
- `css/modes/care.css`: 케어모드 전용 표시 보정
- `css/modes/ai-assisted.css`: AI 연동모드 전용 표시 보정
- `config/gameConfig.js`: 게임 설정, 모드/config 매트릭스, URL/App config 정규화
- `js/audio-display.js`: 오디오 제어
- `js/session-board.js`: 세션 메타와 선택 그룹 수집 유틸
- `js/play-input.js`: 게임 진행, 보드 렌더링, 입력 처리
- `js/result-bridge.js`: 결과 스키마 생성과 브릿지용 결과 처리
- `js/screen-flow.js`: 앱 흐름 및 화면 전환
- `assets/`: 이미지, 오디오, 데이터 리소스

## 9. 개발 시 주의사항

- 작업 전 ClickUp 기획 문서와 요구사항 명세서를 먼저 확인한다.
- 요구사항 파일이 없거나 접근 불가하면 임의로 추정하지 말고 확인 필요 사항으로 남긴다.
- 시니어 사용자가 혼자 조작할 수 있는 단순하고 명확한 흐름을 우선한다.
- 오답이나 중도 실패가 게임 진행을 막지 않도록 한다.
- 정답 공개 여부, 자동 이동, 힌트 동작 등 핵심 규칙을 변경할 때는 문서 요구사항과 비교한다.
- 모바일 가로 화면과 PC 브라우저 양쪽에서 UI가 잘리지 않는지 확인한다.
- 변경 후 가능하면 브라우저에서 실제 화면과 상호작용을 확인한다.
