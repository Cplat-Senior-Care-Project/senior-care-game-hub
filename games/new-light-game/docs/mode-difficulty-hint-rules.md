# 빛나는 전구를 찾아라 - 모드별 난이도, 제한시간, 힌트 동작 정리

작성 기준: 2026-06-19 현재 로컬 구현 기준  
관련 파일: `config/gameConfig.js`, `js/screen-flow.js`, `js/play-input.js`, `js/result-bridge.js`

## 1. 공통 게임 구조

이 게임은 잠깐 켜진 전구 위치를 기억한 뒤, 선택 단계에서 같은 위치를 다시 고르는 위치 기억 게임이다.

기본 진행은 다음 순서다.

1. 기억 단계: 정답 전구가 켜진 상태로 잠시 표시된다.
2. 선택 단계: 전구가 모두 꺼진 상태가 되고, 사용자가 기억한 위치를 선택한다.
3. 피드백 단계: 정답을 모두 맞히면 다음 문제로 넘어가고, 오답이 누적되면 부드러운 안내 후 다음 문제로 넘어간다.
4. 모든 문제가 끝나면 결과 화면으로 이동한다.

현재 구현에서 정답 위치는 매 문제마다 무작위로 선택된다.

## 2. 난이도 로직

난이도 설정은 `DIFFICULTY_CONFIG`에서 관리한다.

| 난이도 키 | 화면 라벨 | 그리드 | 켜지는 전구 수 | 기본 제한시간 |
| --- | --- | --- | --- | --- |
| `easy` | 쉬움 | 2 x 2 | 2개 | 2분 |
| `normal` | 보통 | 3 x 3 | 3개 | 2분 |
| `hard` | 어려움 | 3 x 4 | 4개 | 2분 |
| `reminder_fixed` | 알림 활동 | 3 x 3 | 3개 | 2분 |
| `care_fixed` | 쉬운 활동 | 2 x 2 | 1개 | 2분 |

현재 기본 난이도는 모든 모드에서 `easy`다.

표준모드는 난이도 선택 화면을 보여주므로 사용자가 `easy`, `normal`, `hard` 중 선택할 수 있다. 알림모드는 기본적으로 난이도 선택 화면을 숨기므로 `easy`로 바로 시작한다. 다만 앱 config 또는 URL config에서 `difficulty`, `difficulty_key`, `difficultyKey`, `difficulty_config`, `difficultyConfig` 값을 전달하면 해당 난이도로 시작할 수 있다.

케어모드와 AI 연동모드는 난이도 선택 화면을 숨긴다. 기본 난이도는 `easy`이며, 케어 흐름에서는 선택된 난이도에 따라 목표 전구 수가 보정된다.

| 케어/AI 난이도 | 실제 목표 전구 수 |
| --- | --- |
| `easy` | 1개 |
| `normal` | 2개 |
| `hard` | 3개 |

## 3. 모드별 기본 설정

모드 설정은 `MODE_CONFIG`에서 관리한다.

| 모드 | 문제 수 | 기억 표시 시간 | 전체 제한시간 | 난이도 선택 | 컨디션 체크 | 마무리 체크 | 타이머 표시 | 힌트 |
| --- | ---: | ---: | ---: | --- | --- | --- | --- | --- |
| `standard` 표준모드 | 10문제 | 4초 | 난이도 제한시간 사용 | 표시 | 표시 | 표시 | 표시 | 사용 |
| `reminder` 알림모드 | 10문제 | 4초 | 난이도 제한시간 사용 | 숨김 | 숨김 | 숨김 | 표시 | 사용 |
| `care` 케어모드 | 4문제 | 6초 | 1분 | 숨김 | 숨김 | 숨김 | 숨김 | 사용, 자동 힌트 |
| `ai_assisted` AI 연동모드 | 4문제 | 6초 | 1분 | 숨김 | 숨김 | 숨김 | 숨김 | 사용, 자동 힌트 |

알림모드는 현재 다음 흐름으로 시작한다.

`로딩 화면 -> 게임이 곧 시작돼요! -> 3초 카운트다운 -> 게임 시작`

알림모드에서 컨디션 체크와 마무리 체크는 기본으로 숨겨져 있다. 단 config로 다시 켤 수 있다.

지원하는 config 키는 다음과 같다.

| 기능 | snake_case | camelCase |
| --- | --- | --- |
| 컨디션 체크 표시 여부 | `show_condition_check` | `showConditionCheck` |
| 마무리 체크 표시 여부 | `show_finish_check` | `showFinishCheck` |
| 난이도 선택 표시 여부 | `show_difficulty_select` | `showDifficultySelect` |
| 문제 수 | `question_count` | `questionCount` 또는 `roundCount` |
| 기억 표시 시간 | `exposure_time_ms` | `exposureTimeMs` |
| 전체 제한시간 | `total_time_limit_sec` | `totalTimeLimitSec` |
| 문제당 제한시간 값 | `round_time_limit_sec` | `timeLimitSec` 또는 `time_limit_sec` |
| 힌트 사용 여부 | `hint_enabled` | `hintEnabled` |
| 자동 힌트 사용 여부 | `auto_hint_enabled` | `autoHintEnabled` |
| 자동 힌트 지연시간 | `auto_hint_delay_sec` | `autoHintDelaySec` |

주의: 현재 `round_time_limit_sec` 값은 결과 로그에는 기록될 수 있지만, 실제 문제 진행 제한시간으로는 사용되지 않는다.

## 4. 제한시간 로직

현재 제한시간은 “전체 남은 시간” 중심으로 동작한다.

표준모드와 알림모드는 `modeConfig.totalLimitMs`가 `null`이므로 선택된 난이도의 `totalLimitMs`를 사용한다. 현재 모든 일반 난이도는 2분으로 설정되어 있다.

케어모드와 AI 연동모드는 모드 자체에서 `totalLimitMs`를 1분으로 지정하므로 난이도 제한시간보다 모드 제한시간이 우선된다.

타이머 감소 방식은 다음과 같다.

1. 전체 타이머는 게임 시작 시 생성된다.
2. 실제 남은 시간 감소는 선택 단계에서만 진행된다.
3. 기억 단계, 피드백 단계, 일시정지 중에는 전체 시간이 줄어들지 않는다.
4. 남은 시간이 10초 이하가 되면 타이머 UI에 경고 색상이 적용된다.
5. 남은 시간이 0이 되고 현재 단계가 선택 단계라면 `total_timeout`으로 게임이 종료된다.

현재 선택 단계의 문제당 개별 제한시간은 꺼져 있다. 코드상 `roundTimeLimitMs` 설정값은 존재하지만, 선택 단계 진입 시 `roundEndAt`이 0으로 초기화되고 `updatePhaseTimer(0)`이 호출되므로 문제별 자동 타임아웃은 적용되지 않는다.

문구는 `js/play-input.js`의 `buildMemoryPrompt`, `buildSelectionPrompt`, 힌트/자동힌트 로직에서 관리한다.

| 상황 | 문구 |

| 선택 단계 | `빛나는 전구가 있었던 위치를 골라주세요!` |
| 힌트 표시 중 | `잠시 동안 보여 드릴게요!` |
| 자동 힌트 안내 | 현재 표준/알림에서는 자동 힌트가 꺼져 있어 기본 노출되지 않음 |

### 케어모드/AI 연동모드

| 상황 | 문구 |
| --- | --- |
| 안내 단계 | `불이 켜지는 곳을 같이 볼까요?` |
| 기억 표시 단계 | `불이 켜지는 곳을 같이 볼까요?` |
| 가림 단계 | `좋아요. 이제 같은 곳을 찾아볼까요?` |

| 힌트 표시 중 | `잠시 동안 보여 드릴게요!` |

## 6. 힌트 제공 방식

힌트는 선택 단계에서만 사용할 수 있다. 기억 단계, 피드백 단계, 일시정지 중에는 사용할 수 없다.

힌트가 실행되면 아직 찾지 못한 정답 전구 위치만 3초 동안 강조 표시한다. 이미 맞힌 정답 위치는 힌트 대상에서 제외된다.

힌트가 활성화된 3초 동안은 전구 선택이 막힌다. 사용자가 힌트 표시 중 전구를 누르더라도 선택 처리가 되지 않는다.

힌트가 끝나면 힌트 강조 표시가 사라지고 선택 단계 문구로 돌아간다.

### 표준모드/알림모드 힌트

표준모드와 알림모드는 수동 힌트 버튼을 사용한다.

현재 구현에서는 한 문제당 힌트를 1회만 사용할 수 있다. 한 번 힌트를 사용하면 힌트 버튼은 비활성화된다.

| 항목 | 동작 |
| --- | --- |
| 힌트 버튼 | 선택 단계에서 표시 |
| 힌트 횟수 | 한 문제당 1회 |
| 표시 시간 | 3초 |
| 표시 대상 | 아직 못 고른 정답 전구 |
| 선택 차단 | 힌트 표시 중 선택 불가 |
| 자동 힌트 | 꺼짐 |

### 케어모드/AI 연동모드 힌트

케어모드와 AI 연동모드는 자동 힌트가 켜져 있다.

선택 단계에서 10초 동안 힌트가 활성화되지 않으면 자동 힌트 안내 문구가 나온 뒤 힌트가 실행된다. 사용자가 입력하면 자동 힌트 대기 시간이 다시 예약된다.

케어모드와 AI 연동모드는 `keepsHintButtonActive()`가 true라서 힌트 버튼을 계속 사용할 수 있는 모드로 분류된다.

| 항목 | 동작 |
| --- | --- |
| 자동 힌트 | 켜짐 |
| 자동 힌트 지연 | 10초 |
| 수동 힌트 반복 | 가능 |
| 표시 시간 | 3초 |
| 표시 대상 | 아직 못 고른 정답 전구 |
| 선택 차단 | 힌트 표시 중 선택 불가 |

## 7. 오답, 정답, 다음 문제 이동

선택 단계에서 정답 위치를 누르면 해당 카드에 정답 표시가 적용된다.

한 문제의 모든 정답 위치를 고르면 즉시 정답 처리되고, 마지막 문제가 아니라면 다음 문제 안내 화면을 거쳐 다음 문제로 넘어간다.

오답 위치를 누르면 오답 표시가 적용되고 오답 횟수가 증가한다. 오답이 3회가 되면 `wrong_limit`으로 해당 문제를 종료하고 다음 문제로 넘어간다.

문제 결과에는 다음 정보가 기록된다.

| 항목 | 설명 |
| --- | --- |
| `target_positions` | 정답 위치 |
| `selected_positions` | 사용자가 선택한 위치 |
| `is_correct` | 문제 정답 여부 |
| `attempt_count` | 선택 횟수 |
| `correctClickCount` | 정답 클릭 수 |
| `wrongClickCount` / `wrong_tap_count` | 오답 클릭 수 |
| `first_response_time_ms` | 선택 단계 시작 후 첫 반응까지 걸린 시간 |
| `response_time_ms` | 선택 단계 시작 후 문제 종료까지 걸린 시간 |
| `hint_used` | 해당 문제에서 힌트를 사용했는지 |
| `hint_count` | 해당 문제의 힌트 사용 횟수 |
| `failReason` | 실패 사유. 예: `wrong_limit`, `timeout` 등 |

## 8. 결과 데이터에 남는 설정값

결과 생성 시 현재 설정은 `config_snapshot`과 `result_detail_json`에 남는다.

주요 기록값은 다음과 같다.

| 항목 | 의미 |
| --- | --- |
| `mode`, `app_mode` | 실행 모드 |
| `difficulty` | 선택 또는 전달된 난이도 |
| `question_count` / `total_questions` | 총 문제 수 |
| `grid_rows`, `grid_cols`, `grid_size` | 그리드 크기 |
| `target_count` | 문제당 목표 전구 수 |
| `exposure_time_ms` | 기억 단계 표시 시간 |
| `hint_enabled` | 힌트 기능 사용 여부 |
| `auto_hint_enabled` | 자동 힌트 사용 여부 |
| `show_condition_check` | 컨디션 체크 노출 여부 |
| `show_finish_check` | 마무리 체크 노출 여부 |

## 9. 현재 구현상 주의사항

현재 문서 요구사항과 코드 구현이 다를 수 있는 부분은 다음과 같다.

1. 표준모드와 알림모드의 기억 표시 시간은 현재 4초다.
2. 쉬움, 보통, 어려움의 전체 제한시간은 모두 2분으로 동일하다.
3. 어려움 난이도는 현재 3 x 4 그리드다.
4. 문제당 개별 제한시간은 설정값만 있고 실제 진행 제한시간으로는 적용되지 않는다.
5. 표준모드와 알림모드의 힌트는 현재 한 문제당 1회만 사용할 수 있다.
6. 케어모드와 AI 연동모드의 자동 힌트는 10초 후 실행된다.
7. 알림모드는 기본적으로 컨디션 체크, 시작화면, 난이도 선택, 마무리 체크를 건너뛰고 바로 시작 카운트다운으로 들어간다.
